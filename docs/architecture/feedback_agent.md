# Deterministic feedback decisions (W09 / #139)

`runtime.feedback_loop` implements a single decisioner at completed tool
boundaries. `choose(state, config)` is pure: it cannot read a filesystem, invoke
a calculator or inspect future tool results. Inputs include one mapped fixed atom
pool, explicit gas/charge/spin, candidate and geometry hashes, proposed-event
hashes, protocol identity, sequentially observed evidence and remaining budgets.
Unknown family, generation protocol and uncertainty stay `null`. No reference
product, TS label or sealed evaluation label is accepted in the initial view.

The initial tool profile is **verified reference replay**, not live adaptive
generation. It reads original settled service artifacts and recomputes feedback
with the W08 verifier. All request/result/raw hashes, the original shared ledger,
committed token and pre-call journal must reconcile. Actual endpoint and product
BE hashes and raw result locators are retained along with energy (Hartree),
gradient identity (Hartree/bohr), frequencies (cm^-1), execution status and
layered scientific status. Absent quantities are unknown, not zero.

## Finite actions and current availability

Every action has a version, sequence, visible-state hash, policy/seed, target,
finite parameters, mechanistic question, rationale, expected evidence, complete
resource envelope and content-derived identity. Actions are generated by the
versioned policy; arbitrary supplied actions cannot enter the reducer.

| Action | Current deterministic adapter |
| --- | --- |
| `validate_connectivity` | Verify and import an existing reference attempt, including failures. Does not recompute IRC. |
| `select_sampling_policy` | Persist a choice from the frozen joint/event-lead2 or independently trained serial catalogue. Does not execute generation. |
| `finish` | Close the finite replay and preserve unresolved evidence. |
| `propose`, `resample_event`, `resample_geometry` | Unavailable; live generation adapter still needed. |
| `physical_probe`, `reference_label`, `refine_TS` | Unavailable; bounded scientific adapters still needed. |
| `expand_intermediate` | Unavailable; requires endpoint-to-input contract and W12 execution. |

`fixed` validates the predeclared candidate order and stops. The simple
`evidence_heuristic_v1` records a serial sampler choice after an independently
observed repeated channel or a certified alternative to the planned event.
Software execution failure alone does not constitute chemical disagreement.
Candidate order is deterministically addressed by seed and candidate identity.
Selected samplers do not alter already-generated replay candidates. No LLM is
used, and neither sampler choice nor fixture behavior establishes a better policy.

## Accounting, memory and recovery

`attributed_reference_cost` reconstructs the historical attempt cost visible at
that replay step. It includes failed/unfinished primitives and measured or
conservative resource basis. The same result imported twice is counted once;
two genuinely different attempts reaching one endpoint event count as two paid
attempts and one channel. A cache reread does not trigger the repeated-channel
heuristic. Channel identity includes mapped pool, protocol and actual event.
The full input and result provenance remains queryable in `state.evidence`.

The replay tool consumes zero new calculator calls and zero GPU work. Its current
wall/process-CPU/retained-byte costs are recorded separately by the runner.
Policy comparison is not a new chemical experiment: both policies reuse the same
historical costs, which must not be summed as new spending. Generation, training,
tuning and shared/scheduler overhead are outside attributed reference cost.

All cost axes must be explicit and finite. A complete reference envelope must
fit before its result becomes visible. All observations and overspending remain
recorded, and the next decision stops after an exceeded cap. A maximum of 128
actions is supported; the frozen run allows 16 and reserves a final stop action.
One OS lock serializes the decision store. The manifest pins configuration,
initial inputs and tool/result identities. Each action is durable before tool
execution; the outcome is durable before the hash-linked state transition.
Recovery rebuilds the state, re-verifies every outcome and checks identical
decisions. A state-write failure therefore cannot lose endpoints or charge a
result twice. Failure records distinguish tool, report-write and settlement
phases and are retained individually. Original certification files are read-only;
their existing token/cache recovery is not modified or replaced.

## Real replay and remaining work

`scripts/replay_feedback_loop.py` freezes the two original job-4096 results,
including the interrupted attempt, as separate atom-pool episodes. It runs fixed
and heuristic policies, resumes each trace, compares all durable bytes and checks
the original evidence stayed unchanged. Selection was retrospective and deliberate;
this is a real-feedback integration check, not blind performance evidence.

Use a new clean checkout and fresh output directory on n2. Set the source SHA,
checkout, original panel and output variables explicitly in a dated run record:

```bash
source ~/miniconda3/etc/profile.d/conda.sh
conda activate xtbflow
cd "$XTBFlow_AGENT_SOURCE"
test "$(git rev-parse HEAD)" = "$XTBFlow_AGENT_COMMIT"
export OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 MKL_NUM_THREADS=1
srun --partition=main --nodes=1 --ntasks=1 --cpus-per-task=1 --mem=2G \
  --time=00:05:00 timeout 180 python scripts/replay_feedback_loop.py \
  --reference-panel "$XTBFlow_ORIGINAL_PANEL" --out "$XTBFlow_AGENT_OUTPUT"
```

The runner bounds work to 120 seconds, 16 MiB inputs and 16 MiB outputs, one CPU,
zero new calculator calls and zero GPU. Slurm also bounds process/setup overhead.
The repeated-channel behavior is tested with fixtures only. W09 still needs two
real adaptive loops: reallocating exploration after repeated physical channels,
and acquiring information after physical disagreement then generating a changed
proposal. Live tool adapters, full cost comparison (#140), and intermediate
expansion (#142) remain incomplete. This PR does not complete W09.
