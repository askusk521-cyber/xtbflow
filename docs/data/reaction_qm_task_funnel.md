# Reaction-QM 任务准入漏斗

对应 issue #76 / #94(第1线,数据)。本文档说明漏斗怎么判、结果是什么、哪些结论**不能**下。机器可读结果见
[`docs/evidence/reaction_qm_task_funnel_20261006.json`](../evidence/reaction_qm_task_funnel_20261006.json)。

**这是任务准入统计,不是训练集准入。** 没有任何记录因此被升级为 `development_*` 或 `confirmatory`;
接入统一 `TrackBRecord`、许可审查和分组冻结仍是后续步骤。

## 关键判定规则

- **事件标签**只来自 TS 反应式两侧的图差分(键级 `product − reactant`,符号约定与 `dft_da._event_edits` 一致),
  不需要端点映射。芳香键、非整数键编辑、无键变化的记录不给事件标签。
- **端点局部编号 → 全局编号**:端点物种的 map 编号是局部的。对应只在以下情形才认证,并做往返校验(元素、全部键、键级、电荷):
  - `unique_graph`:图同构唯一;
  - `symmetric_noncenter`:有残余对称,但反应中心原子都不在对称等价类里。
  - 元素序列一致**不**当作映射证据。10-06 的探索还表明,端点局部编号与全局编号的单调对应只在约 76% 的(端点物种, TS 分量)配对里成立(4,500 条记录的探索样本),不能当通用规则。
- **表示冲突**:端点物种与 TS 同侧分量元素和连接相同但键级/电荷不同(例如同一 S–S 一处单键一处三键),
  这时基于键级的事件标签依赖表示,暂不给出(`endpoint_representation_mismatch`)。
- **分组**是项目派生规则 `reaction_qm_reactant_product_set_union_v1`:反应的反应物集合与产物集合(去 map、去立体)互相连通,
  正逆反应和共享物种的链条归为一组;不是官方家族标注。

## 对结果的理解

1. **paired_joint 的 11,375 是保守下限**。未认证的主要是中心对称歧义:
   - 若氢原子的对称歧义(例如甲基三个 H 谁转移)能由有证据的规则解决,可达 20,013 条(17,778 母组);
   - 若所有中心歧义都解决,可达 32,883 条(28,473 母组)。
   这些数字只量化"值得做什么",**没有任何一条被准入**。
2. **官方 ID 划分会泄漏母体系**:范围内 33,000 个项目派生母组中,有 1,447 个跨越官方 train/valid/test 的多个分区。
   训练时应按项目派生母组划分,官方划分单独保留。
3. **事件/TS 配对的无标签合理性证据**(不是准入门槛):事件中成键/断键原子对在 TS 里的最大距离,中位数 2.43 Å,p90 3.11 Å,
   p99 4.51 Å;4,878 条超过 3 Å,756 条超过 4 Å。超过 4 Å 的记录配对可疑,后续应单独抽查。
4. **单个 TS 与该步骤的对应在本阶段只是来源声明**;下文"IRC 阶段"用 IRC 路径给出了几何证据。

### 怎么判的,以及这些数字能说明什么

- **单位不靠假设**:用 `ΔE ≈ −½(F_i+F_{i+1})·Δx` 的功恒等式沿路径测。斜率≈1 说明能量与力在存储单位下互相自洽;
  绝对单位另由 IRC TS 能量(eV)与主文件 TS 能量(Hartree)逐条对照确认。
- **IRC 用自己的坐标系**:约三成记录的 IRC 帧 0 相对主文件 TS 有整体旋转/平移(原始坐标差 6–8 Å,但能量一致)。
  所以按刚体对齐后比较;换原子顺序或换结构仍会被拒。
- **步骤配对**:对事件点名的每条成键/断键 σ 边,看两个 IRC 端点之间的距离变化方向是否与事件一致(0.05 Å 死区),
  要求没有一条反向、至少一半明显变化。这说明"事件—TS—路径"三者互相一致,**不证明**反应机理。
  IRC 端点常常没有完全弛豫到产物,所以不用绝对键态做主判据;绝对键态作为严格档单独计数。
- **方法修订要如实说明**:方向性判据是在 800 条冒烟样本里看到 77 条"矛盾"其实只是端点没弛豫之后才定的,
  原来的绝对键态判据会把它们误判。全量结果与那 800 条有重叠。
- **路径帧不是独立样本**:4,296,626 帧来自 37,898 条路径,同一路径的帧强相关。按母组(32,803)和路径数而不是帧数估计覆盖。

### 一个必须守住的边界:IRC 端点不能当盲输入

IRC 端点帧是从 TS 顺着路径往下走得到的反应就绪复合物。`configs/task.yaml` 禁止"由目标 TS 反选的反应就绪构象"作为盲推理输入,
所以这些帧的来源标为 `irc_end_frame_ts_derived`,`reactant_geometry_blind_input_safe = false`。
32,117 条是"事件、TS、路径互相一致"的**配对监督证据**,不是可直接喂给盲评估的反应物输入。
盲输入仍应来自独立优化的端点物种,那需要端点局部→全局的对应;IRC 可以作为解决这个对应(例如哪个 H 在反应)的**证据**,
这是下一步,尚未做。

## 证据边界

- 许可:Zenodo API 元数据显示该记录许可为 **CC-BY-4.0**(开放获取,2026-10-06 核对;此前 #71 记录页上看不到机器可读许可,以 API 为准)。使用需署名(DOI 10.5281/zenodo.18551029 及数据集论文)。逐记录的第三方来源未独立核验。仓库只保存身份、哈希和汇总,原始字节不进仓库(体积与 #87 的大文件规则),外部清单见 `data/external/reaction_qm_v2.json`。
