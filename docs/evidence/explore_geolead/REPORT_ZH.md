# 几何先行时钟：能否给物理信号留出窗口（探索性）

本报告全部结果为探索性，只用 V1a 开发集（62 个母体、21 个分子式组），V1b 按负责人决定暂缓，不改变任何既有决策。几何先行时钟把事件定型的中位时刻从 0.50 推迟到 0.58（t_b=s²）和 0.62（t_b=s³），预测终点上 xTB 信号变得有用的时刻仍是 s≈0.7，于是窗口比例从 14.5% 升到 27.9% 和 34.6%；无引导生成质量几乎不变（最佳参考命中率差 −0.2 和 −0.4 个百分点），两条路径按预写规则均判为 `GEOMETRY_LEAD_OPENS_WINDOW`。

背景：PR #110 的检查 B 发现，同步时钟下预测终点的 xTB 能量要到 t≈0.7 才有信息，此时 85% 的事件已定型（`NO_USABLE_WINDOW`）。联合生成器训练时 t_b、t_x 独立采样，所以可以不重训、直接换时钟。配置 `configs/explore/geometry_lead.json`（geolead-1）在运行前提交；代码 `4ccc4fa`，n2 上从该 SHA 的干净克隆运行。

## 设计

- 三条路径共用检查 B 的全部定义（3 个训练 seed、每母体每 seed 32 条、无引导、同一套信号与读法），并用相同的语义噪声键，每条轨迹在三条路径上起点完全相同：
  - `sync`：t_b = s，t_x = s（重跑，用于复现检查 B）；
  - `geometry_lead2`：t_b = s²，t_x = s；
  - `geometry_lead3`：t_b = s³，t_x = s。
- 所有时间都是积分参数 s（三条路径上都等于 t_x）。
- 质量容差沿用 V1a 基线复核的限值：最佳参考命中率下降 ≤ 0.05、合法率下降 ≤ 0.10（点估计）。

**复现**：sync 重跑与检查 B 的轨迹文件 SHA-256 完全相同（`bb104be0…`），5,952 条轨迹的最终事件、代理状态和定型步全部一致。

## 解读

1. **窗口是靠推迟事件打开的，不是靠几何提前成熟。** 三条路径上 t_x 都等于 s，xTB 信号的时间曲线几乎重合（t_geo 都是 0.7）；变化的只是事件定型更晚。窗口比例随推迟程度单调增加（14.5% → 27.9% → 34.6%）。
2. **代价很小。** 合法率下降约 1.5 个百分点（区间不含 0，但远在 10 个百分点的容差内），最佳参考和最佳事件命中率的变化都在 ±0.4 个百分点以内、区间含 0。
3. **窗口仍然只覆盖约三分之一的轨迹。** 即便用 t_b=s³，物理信号变得有用时（s≈0.7）仍有 65% 的事件已经定型；而且那时信号本身也只是中等强度（ρ≈0.33）。
4. **学习型 h_X 信号的窗口反而变小**（46% → 35%），因为它依赖事件状态 b_t，事件推迟后它的信号也推迟了。这与 PR #110 的判断一致：h_X 的早期相关有一部分来自事件状态，而不是几何。

## 对下一步的含义

几何先行时钟可以几乎无代价地给真实物理留出约 30% 的窗口，这是"让物理在事件定型前介入"第一次有了可作用的空间。但它还没有回答物理信号能不能真的改写事件。下一步若要检验，需要按交接第 6 条先单独设计鞍点感知的物理引导（例如复用仓库中的 G_sad 方向，或只用于淘汰/重采样并配 TS 性检查），不能直接对 E(x̂₁) 做梯度下降。本报告不实现任何物理引导。

## 偏差、限制与披露

- 两条几何先行路径都报告，没有按结果挑选其一。
- 开发集曾参与 V1a 调参，也已用于 PR #110；本报告只用于方向判断。
- t_b=s³ 第一步的事件增量为 8×10⁻⁶，从 float32 轨迹反推的 b̂₁ 在最初几步约有 1% 的相对误差；那时事件本来就解码不出，不影响定型时刻。
- 质量指标是单条轨迹层面的比例，不是 V1a 预算曲线上的召回；引导与成本均未测试。
