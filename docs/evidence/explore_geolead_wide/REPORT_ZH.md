# 窗口推大：更强的事件推迟（geolead-2，探索性）

本报告全部结果为探索性，只用 V1a 开发集（62 个母体、21 个分子式组），V1b 暂缓。把事件推迟得更多，窗口只再增加一点就趋于平台：t_b = s⁴ 的窗口为 37.6%（s³ 为 34.6%），合法率代价增至 −2.1 个百分点；先冻结事件到 s=0.3 或 0.5 再推进，窗口为 22.2% 和 31.8%，不如幂次时钟。所有路径按预写规则均为 `GEOMETRY_LEAD_OPENS_WINDOW`。

配置 `configs/explore/geometry_lead_wide.json`（geolead-2）和代码 `1efad90` 均在运行前提交。新路径用记录式积分（端点预测直接取网络速度，事件冻结期间也有定义）；该积分下的 `geometry_lead3` 与 geolead-1 逐条一致。

## 解读

1. **窗口在约 35–38% 处趋于平台。** 物理信号的时刻由几何时钟决定（三条路径上 t_x 都等于 s，t_geo 都是 0.7），推迟事件只能推迟到这么多：s⁴ 下仍有 62% 的事件在 s=0.7 前定型。
2. **事件的"决定"并不完全靠事件变量本身推进。** 在 delay50 中，事件变量在 s=0.5 之前完全停在初始噪声上，但已有 30% 的轨迹在 s=0.5 前定型——网络从正在成熟的几何读出了最终事件。这说明联合模型里，几何本身在承载事件选择；单纯冻结事件变量无法无限推迟决定。
3. **代价随推迟缓慢增加。** s⁴ 的合法率下降 2.1 个百分点、最佳事件下降 0.7 个百分点（区间刚好含 0），仍在 V1a 容差内，但边际收益（窗口 +3 个百分点）已经很小。
