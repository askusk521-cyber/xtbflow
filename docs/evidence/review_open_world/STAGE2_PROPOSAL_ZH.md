# 第二阶段提案：至多十条 xTB 新通道的 DFT 认证（仅提案，未运行）

本提案及其依据全部为探索性，不宣称已经发现经 DFT 认证的新反应。第一阶段的完整结果见同目录 REPORT_ZH.md 与 results.json；仅当阳性对照闸门通过时才考虑以下方案。

## 入选规则

仅从冻结 OUTSIDE_CATALOGUE_EVENT 样本中选择第一阶段状态为 STRICT_JOINT_GRAPH_VALID 的候选，且同母体基准链也必须通过相同严格认证。按第一阶段 ΔEa_xTB 从小到大排序，以 sha256(candidate_id) 打破平局，每母体最多一条，取前十条；若不足十条，不补采新候选。该规则有意优先检验 xTB 上最有竞争力的新通道，不能用于估计所有目录外候选的无偏 DFT 通过率。

## 拟用协议与成本

经负责人明确批准后，使用既有 V1b DFT 链的协议 v1b-h-gpu4pyscf-3（ωB97X/6-31G(d)，gpu4pyscf；严格鞍点、双向 IRC、端点频率和图身份认证）。这里仅引用协议作为未来方案，不启动或修改 V1b。

已有 D1 每条链实测约 0.68 GPU 小时，因此十条候选预计约 6.8 GPU 小时。若需与同母体已知最佳通道作 DFT 势垒差比较，还需要对最多十条基准链执行同等级认证，额外约 6.8 GPU 小时，总计最多约 13.6 GPU 小时。以上为历史平均数推算而非预算保证；失败重试和额外诊断须另行批准。所有 GPU 任务必须通过 Slurm，遵守项目串行约束，每个作业不超过两小时。

## 判定与交付

逐条报告成功及失败阶段，不能把 SCF 或优化失败当作不存在该通道。只在候选和基准均通过 DFT 严格认证后比较电子势垒，不混用 xTB 和 DFT 能量，不据十条择优样本推出总体发现率。保留配置冻结提交、原始日志、梯度调用与计时、各链 verdict、环境版本和哈希；DFT 阶段需单独分支及 PR。
