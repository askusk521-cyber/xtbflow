# n2 GPU 驱动不匹配导致的三次作业失败（2026-10-10）

本文件记录基础设施事件，不是科学结果。

## 发生了什么

第二版调度器启动后，连续提交的 Slurm 2825、2826、2827 都在约 1 秒内失败：
- 2825：母体 `5b2d3d450552ae85d0f4` 的候选链 `c538c83b728169fe`；
- 2826、2827：母体 `e193d2b0c22148150613` 的反应物 `7e440ab552b5e1e9` 和参考链 `793ad9d251fc8b33`。

执行程序在开始任何量化计算之前调用 `nvidia-smi` 记录环境，得到退出码 18；`stage_timings` 为空。在 n2 上直接查询的结果：
- `nvidia-smi`：Failed to initialize NVML: Driver/library version mismatch；
- NVML 用户态库版本 595.99（`libnvidia-ml.so.595.99.02`）；
- 已加载的内核模块是 595.91.07；
- 节点自 2026-09-20 起没有重启过。

也就是说，NVIDIA 用户态库被升级了，但内核模块没有重新加载。这会影响 n2 上所有用户的 GPU 计算，需要管理员重启节点或重新加载驱动模块。本项目不做任何系统级修改。

## 影响与处理

- 第二版调度器把这三次失败当作链异常，连续三次后按规则停下，合计 GPU 6 秒，没有浪费算力。
- 这三项在任何量化计算之前就失败了，不是冻结协议的一次尝试，也不是化学结论。
- 第三版调度器 `scripts/review_open_world_dispatch_v3.py` 做了三处修正：
  - 没有任何量化阶段记录的失败归为基础设施故障，立即停下；
  - 开始提交前，先在 Slurm 里用 `nvidia-smi` 做一次 GPU 预检；
  - 加 `--quarantine-preqc` 选项时，把这类空工作目录原样移到 `o2-run-preqc-failed/`，并写下来源记录，让未改动的执行程序能对这些项做第一次真正的尝试。
- 2753 已经进入 IRC 阶段，属于协议内的尝试，永远不会被移动，也不会重跑。
- GPU 恢复之前不提交任何新作业。
