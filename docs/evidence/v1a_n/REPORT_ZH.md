# V1a-N NFE 对齐串联对照报告（探索性）

**本报告为探索性分析：V1a 正式集已揭盲一次，结果不是确认性证据，V1a 正式决策 `GO_V1b` 不变。主对比 AUC(B0-50) − AUC(A0-25+25) = −0.0160，双侧 95% 聚类区间 [−0.0451, +0.0131]，区间下限不大于 0；按预先写定的解读，V1a 中 B0 的预算优势可以由积分步数解释，不能归功于联合生成。**

（P=342 母体，G=70 分子式组；三个训练 seed 在母体内平均，采样 seed 0；V1a 的联合终点 AUC 定义与 5 个预算点。）

## 1. 做了什么

- 新增两臂，全部无引导，使用 V1a 冻结检查点、冻结成本表（SHA256 `6c142a6b…`）、冻结路径 `sync` 和 `efficiency` 噪声命名空间（与原 A0/B0 共享起点噪声）：A0-25+25（事件 25 步 → 解码 → 几何 25 步）、B0-25（联合 25 步）。原 A0（50+50）、B0（50）直接复用封存流，没有重跑。
- 配置 `configs/v1a_n/nfe.json` 在提交 `a6b47d2` 冻结，早于任何正式集生成；冒烟测试（10 个开发母体，`smoke.json`）在冻结前通过：每个完成尝试的步数精确为 25、各网格时钟增量之和为 1、解码与代理匹配正常、输出不在封存目录内。
- 正式集生成：Slurm 2669–2671（每个 seed 1 张 GPU），A0 约 188 s、B0 约 154 s 每 seed，合计约 0.29 GPU 小时（冒烟前预估 0.17–3.5 GPU 小时，远低于 20 小时上限）。评估沿用 `v1a_stream_evaluate.py`（账本审计、代理匹配）；比较由 `09ed7f0` 的 `v1a_n_compare.py` 完成，所有输入对 freeze、`SHA256SUMS`、任务 R 抽取和 N 配置核验通过。

## 4. 主对比与次要结果

- **主对比（预先写定）**：AUC(B0-50) − AUC(A0-25+25) = −0.0160 [−0.0451, +0.0131]（单侧 95% 界 −0.0403 / +0.0084）。下限不大于 0 → "B0 的预算优势可由步数解释"。
- **次要：步数敏感性（任务 R 分析 A，同样完成候选数）**。两种架构把步数减半都几乎不损失单候选命中率：A0-25+25 − A0-50+50，联合终点 n=1…16 的差在 −0.0010 到 +0.0029 之间，区间都含 0（n=4：−0.0010 [−0.0075, +0.0055]）；B0-25 − B0-50 在 −0.0029 到 −0.0019 之间（n=4：−0.0029 [−0.0062, +0.0003]）。事件级终点相同。覆盖率均为 100%。
- **描述性**：同为减半步数时，B0-25 − A0-25+25 = +0.1028 [+0.0759, +0.1298]；步数减半各自带来的 AUC 增益为 B0 +0.1188 [+0.1089, +0.1287]、A0 +0.1283 [+0.1181, +0.1385]；V1a 原对比 B0-50 − A0-50+50 = +0.1123 [+0.0839, +0.1407]。

**读法。** 50 步在这两种架构上都多余：25 步的候选质量不变，候选数翻倍。所以 V1a 里 B0 相对 A0 的 AUC 优势等价于"每个候选少花一半网络调用"，而串联把每段步数减半就能抵消；在每候选调用数相近（0.90 倍）时两者 AUC 无可分辨差异。这和任务 R 的结论一致（同候选数下 B0−A0 无差别）。B0-25 仍高于 A0-25+25，原因同样是每候选成本（25 对 46 单位），不是候选更好。

## 5. 局限

1. 只测了 25 与 50 两档步数，没有找到质量开始下降的步数；"减半不损失"不外推到更少步数。
2. A0-25+25 的非法事件比例略高（INVALID_EVENT 占尝试的 7.6%–10.3%，V1a A0 为 6.0%–8.2%），这部分成本已计入预算轴。
3. 成本按冻结的逻辑单位记账；大分子两档 A0-25+25 的单位成本比 B0-50 低 25%。
4. 只做无引导两臂；引导臂（A1、A2、B1）的步数敏感性未测。
5. 全部是 Transition1x 目录代理命中，不是频率/IRC 认证的 TS；未运行任何量化计算。
