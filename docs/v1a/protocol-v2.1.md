# xtbflow V1a 第一轮验证推进指导：已知通道代理筛查

2026-10-07 · v2.1 · 先检验发现效率与事件反馈，再投入 DFT 认证

> **v2.1 修订要点（相对 v2.0）**
>
> 1. **机制量改为两个对比的交并检验。** v2.0 的逐对 `U(F_S) − max{U(F_0), U(F_R)}` 对两个带噪结果取最大值，期望系统性偏负：评分方向平均同时胜过不推和随机推各 +0.02 时，其真值约为 −0.014（第 7.5 节模拟）。现改为分别检验 M_0 = E[U(F_S) − U(F_0)] 与 M_R = E[U(F_S) − U(F_R)]，两项下界都大于 0 才算机制通过。闸门、功效表与配置同步更新。
> 2. **3 个训练 seed × 1 个采样 seed，取代 1 × 3。** M0 三个种子的 Δ 标准差约 0.07，与目标效应同量级；训练是 V1a 最便宜的部分。评估工作量不变。
> 3. **B0 基线对照改用在 V1a 训练切分上重训的单时间联合模型。** M0 的 B 见过从官方训练集留出的开发与正式母体，且训练数据更多，直接对照会误报退化。
> 4. **成本按网络调用记账。** 预算单位改为“B0 等效候选”，按冻结的逻辑执行顺序累计前向与反向调用，不受批处理效率影响；GPU 墙钟另报。
> 5. **新增开发期引导漂移检查。** 引导梯度不指向参考 TS；若引导抬高同事件候选的参考 RMSD，按预设候选提前结束引导。事件级最佳通道 AUC 成为必报的关键次要指标。
> 6. **写明留出代价与分子式分布检查。** 留出约 300 个正式母体和约 60 个开发母体会使生成器训练数据减少约三分之一；任务 0 必须先统计每个分子式的母体数。
>
> 第 9.7 节的功效数字已按 v2.1 闸门重算（`v1a_gate_power_v21.py`）。在原工作假设下，v2.1 闸门达到 80% 联合 GO 约需 320 个母体。

## 0. 执行代理须知

V1a 回答一个问题：**只给反应物，在相同在线计算预算下，几何反馈能否让耦合生成比强自适应串联搜索更快找回低势垒的已知通道，并且确实把事件分布推向更有利的方向？**

本轮先用 Transition1x（下称 T1x）的已知事件、参考结构和已有 DFT 能量做代理筛查。V1a 不启动新的 xTB、DFT、OptTS、频率或 IRC 计算。通过后，按配套《xtbflow V1b 第一轮验证推进指导》检查代理假阳性与物理有效性。“不做新增量化”不等于没有 CPU 数据处理，也不等于训练、推理和评估没有成本。

本文件替代旧 V1 的样本量、评分器标签来源、主终点、机制规模、量化提名、日程和 GO/HOLD/NO-GO 闸门。旧 V1 中的泄漏隔离、可寻址随机数、守恒投影、同步状态更新、完整事件轨迹回放、失败计费、fallback 不算成功，以及 A2/B1 共享评分与几何引导实现继续保留。旧 V1 的“12 个 H 母体＋10 项同时通过”不得与本文件叠加。

**读法。** 按任务 0—任务 6 执行。每项任务都给出输入、步骤、实现接口、验收与停止条件。代码块中的纯函数是实现规格；涉及模型、调度器和真实仓库的命令是需要实现的目标接口，不代表这些脚本已经存在。当前交付是执行指导及统计复现材料，不是完成训练或量化实验的结果报告。

### 0.1 本轮硬性规则

1. 只做 V1a 的冻结筛查。V1b 的量化队列保持为空，直到 V1a 给出 `GO_V1b`。
2. 五个效率臂是 A0/A1/A2/B0/B1；B2 是配对机制控制。A2 必须允许部分展开、几何引导、淘汰及重新提议事件。
3. A0/A1/A2 共用同一对串联生成器；B0/B1/B2 共用同一个耦合生成器。A2/B1/B2 共用同一份 h_X 权重、分数、梯度与位移限制代码。
4. 生成器、评分器、调参集、冻结评估集按分子式隔离。官方测试集或以前看过的测试集不能通过改名变成新的独立确认集。
5. 采样器只接收反应物和当前生成状态。产物、参考 TS、目录通道数 K、参考势垒、目录匹配结果不能进入在线生成、排序、预算分配或早停。
6. 代理命中必须写成 `PROXY_MATCH`。它只说明接近一个冻结的参考记录；不写成真实 TS、实际 DFT 势垒或完整动力学结论。
7. 所有成本点从同一条、事先冻结调度的生成流截取。不能为 4、8、16、32、64 各运行一套事后挑出的搜索策略。
8. proposal、训练 seed、采样 seed、时间快照、脉冲幅度都不是新的独立母体。推断按母体配对，并保留分子式聚类。
9. 主指标只有一个；机制闸门只有一个，由 M_0、M_R 两个预设对比按交并检验组成。预算点、罕见度分层、事件级 AUC、B1−B0、B1−B2、近最优窗口和多样性用于解释，不再各设一个必须显著的闸门。
10. 先用开发数据规划样本量与整套闸门功效，再冻结评估。不能看过正式 B1−A2 后，以“补功效”为由追加母体、换种子或改主指标。
11. 一切实测数值来自日志；未测填 `null`。本文中的阈值是设计值，统计复现中的数值是特定假设下的计算值，均不等于 xtbflow 实测结果。
12. 只增加完成本实验必要的少量文件和字段。复用 M0 数值、解码、缓存与训练基础设施，不新建通用审计平台。
13. 沿用 M0 每任务一个可审查变更的节奏；实际仓库采用 PR 时附真实验收输出和变更摘要。常规 CPU 单元验收控制在 5 分钟内；训练、全量评估和量化校准不塞进常规 CI。

### 0.3 明确停止范围

| 状态 | 含义 | 后续动作 |
| --- | --- | --- |
| `HOLD_DATA` | 切分、映射、能量来源或检查点暴露量无法确定 | 修复数据；不计算正式方法优劣 |
| `HOLD_BASELINE` | B0 在同步路径明显退化，尚未排除实现或训练原因 | 在开发集修复一次，重新冻结 |
| `HOLD_SCORE` | 评分在真实 rollout 上没有可用信号 | 修评分；不把没有有效引导解释为 H1 失败 |
| `HOLD_POWER` | 实际独立组数和开发方差达不到计划功效 | 报可识别效应，缩小主张或另定新方案 |
| `NO_GO_RESOURCE_SMALL` | 主效应上界低于预先规定的目标收益 | 停止本配置的 DFT 投入 |
| `NO_GO_MECHANISM_SMALL` | M_0 或 M_R 任一项的上界低于预定有用幅度 0.02 | 停止当前事件反馈配置的投入，不宣称机制效应≤0 |
| `NO_GO_WINDOW_THIS_CONFIG` | 正式统计未给出 GO，且在已验证的范围内多档脉冲均无可用事件响应 | 作为不推进的诊断原因，保留模型与窗口限定语 |
| `GO_V1b` | 主比较与机制支持进一步认证 | 启动 V1b 的校准和已冻结抽样 |
| `HOLD_INCONCLUSIVE` | 固定样本跑完但区间仍不足以决策 | 交付完成报告；V1b 不自动启动 |

`HOLD_INCONCLUSIVE` 是可交付的筛查结果，不是继续花钱直到出现 GO 的许可。在冻结的最大预算内没有解决的不确定性，保持为不确定性。

## 1. 实验定义与默认规模

### 1.1 H1 与唯一主比较

H1 的操作性表述是：**在生成尚未完成时，用当前几何的势垒相关分数施加干预，能经由耦合生成器改变后续事件，并提高低势垒已知通道的发现效率。**

主要比较固定为 B1−A2。只胜过 A0 或 B0 不足以推进，因为 A2 已经能够重新提议事件，并用同一评分器在固定事件下优化和分配几何搜索。

默认主终点是五个预设成本点上的“最低已知参考通道联合召回”归一化 log-budget AUC。成本以 B0 等效候选为单位，按网络调用计数（第 8.1 节）。16 等效预算处的二元召回差、事件级最佳通道 AUC 单独列出，但不作为第二个主闸门。完整定义见第 9 节。

### 1.2 五个效率臂与 B2

| 臂 | 生成方式 | 引导与搜索 | 用途 |
| --- | --- | --- | --- |
| A0 | 独立串联 g→h | 无引导，完成候选后统一评分 | 基础串联 |
| A1 | 独立串联 g→h | h_E 引导事件；随后固定事件生成几何 | 无当前 TS 几何的事件评分 |
| A2 | 强自适应串联 | 部分几何展开、h_X 排序、固定事件几何引导、晋级、重新提议 | 主对照 |
| B0 | 耦合生成 | 无引导，完成候选后统一评分 | 共享检查点的无引导能力 |
| B1 | 耦合生成 | 只对 x 施加 h_X 梯度，b 由耦合速度继续更新 | 主方法 |
| B2 | 事件轨迹回放 | x 接受同样干预，b 回放配对 B0 的完整轨迹 | 检查事件反馈的作用 |

B2 不进入五臂效率排名。其 shadow 与回放开销单列；机制比较按相同起点、proposal 和步数配对，不因额外记录开销削减 B2 的样本量。

### 1.3 规模与种子的准确含义

| 项目 | 默认规格 | 允许变化的条件 |
| --- | --- | --- |
| 正式评估母体 | 先按 300 估算资源，最终在 200–350 内规划 | 用开发方差、分子式组数和整套功效计算后冻结；超过 350 返回 `HOLD_POWER` |
| 开发母体 | 默认约 60 个，按分子式与训练集、正式集隔离 | 承担时间窗、强度、A2 时点、漂移检查和功效 nuisance 估计；不得复用正式母体 |
| 已知通道数 | K≥2，无 K 上限 | 映射或数据缺陷可预先排除，不能因 B1 表现排除 |
| 查询构象 | 每母体一个固定 R 锚点 | 主分析不靠 RMSD≤0.30 Å 的同盆地限制筛掉柔性分子 |
| 训练 seeds | 0、1、2；A 的 g/h 与 B 的 f 各训练三份，第 k 份 A 与第 k 份 B 配对 | 三份模型的平均仍是条件于这三次训练的筛查，不估计重训练方差 |
| 采样 seed | 每个训练 seed 只用采样 seed 0 | 采样噪声已由每个预算内的多个候选部分平均 |
| 机制起点 | 每母体×8 proposals×3 训练 seeds | 三幅度和随机方向在同一起点上配对 |
| 主成本点 | 4、8、16、32、64 个 B0 等效候选 | 按网络调用计数（第 8.1 节）；不是强行统一候选数 |
| 主机制时刻 | 每条冻结采样路径一个 t* | 由开发集的时窗扫描选择；正式集不重新挑时刻 |

**为什么用三个训练 seed。** M0 三个种子的 B−A 差值为 −0.038、+0.061、−0.068，标准差约 0.07（训练与采样随机性混合，无法分离），而 V1a 的目标效应是 AUC +0.05。只用一个训练 seed 时，一次训练的运气会直接变成 GO 或 NO-GO，且第 9 节的区间不覆盖这部分不确定性。生成器单次训练约 0.45 GPU 小时（M0 实测），把采样 seed 换成训练 seed 不增加评估工作量。

**留出的代价。** 正式母体与开发母体都必须从可用训练池中留出。按方向规划中约 1,075 个母体估算（实际数由任务 0 重新统计），留出约 300 + 60 个母体后，生成器训练母体减少约三分之一。这对机制筛查可以接受，但 V1a 的绝对召回不能与 M0 的数字直接比较；报告必须列出实际训练母体数和反应数。

若现有检查点严格未见新的评估组，优先复用。M0 检查点在官方训练集上训练，从该集合留出的母体对它们不是未见数据，因此正式运行默认在新切分上重训全部生成器。若没有 200–350 个可留出的母体，选分子式分组的 5 折 out-of-fold 方案。五折意味着每折都需要自己的生成器与评分器；不能用一个看过全部数据的生成器，只给评分头做五折。

“约 1,075 个母体”“约 8,000 条反应”等数目来自本轮讨论中的方向规划，实际可用数必须由清单重新计算。本文件不把它们当作已经核实的缓存规模。

### 1.4 为什么改为曲线

4–64 的预算范围覆盖紧预算与可能饱和的区间。某臂在 64 处已经枚举完已知目录，不代表它在 4 或 8 处也同样有效。主 AUC 给每个预算倍增区间相同权重，防止最大的预算点支配结论。

必须同时保存各成本点的完成候选数、合法事件数和不同事件数。这样能够判断收益来自更多廉价候选、较早覆盖罕见通道，还是几何参考匹配率提高。不能只报一条漂亮的 AUC 数字。

| 单候选连到相邻构象即主失败 | 图级成功与构象偏移分开；严格构象分析另报 |

## 3. 任务 0：核对数据、模型、基线和实际预算

**输入：** 当前仓库、M0 配置与检查点、已授权的数据缓存和计算节点。  
**输出：** `audit.json`、`cohort_counts.json`、`cost_calibration.json`、训练与运行工作量表。  
**完成标准：** 知道哪些资产可复用、哪些必须重训、真正可评估多少独立组，以及一周目标是否有计算依据。

### 3.1 审计顺序

1. 记录仓库提交、M0 指导对应实现、Python/PyTorch/CUDA 与设备型号。只记录实验会用到的版本。
2. 核对 train/val/test 的反应、母体、分子式；统计每层交集和过去是否看过结果。
3. 检查每个生成器及评分器的训练清单 hash。无法证明未见评估数据的权重，只能用于开发。
4. 检查元素索引与真实原子序数。M0 的 1/2/3/4 编码与 Z=1/6/7/8 不能混用。
5. 检查能量单位、反应方向、参考 TS 来源，尤其不能把原始上游数据的不同泛函势垒混入 T1x。
6. 实际数出 K≥2 的母体、分子式组与组大小，输出每个分子式的母体数分布、组数 G、最大组占比和前 10 个最大组。先定可行的分组方式，再确定最终 N（见下文“分子式分布”）。
7. 选开发样本进行推理、梯度、评分与数据匹配测速，同时测出第 8.1 节网络调用成本表。此时不启动正式五臂评估。
8. 给出总 GPU 工作量与日历时间；若需要五折重训，明确展开五份计算。三个训练 seed 的生成器训练量按第 11.1 节计入。

**分子式分布。** 第 9 节的功效工作模型假设每个分子式约 4 个母体。T1x 的分子式分布可能很偏：若少数分子式装了大量母体，有效组数 G 会远小于 N/4，聚类设计效应也会远大于 1.3，这是 300 个母体不够用最可能的原因。允许在冻结前预先规定一次缓解：正式集每个分子式最多保留 `max_parents_per_formula` 个母体（按母体 hash 排序取前若干个），以换取更多独立组。该上限只能依据 `cohort_counts.json` 设定，不能依据任何方法输出。

### 3.2 切分与重训练开销

优先级如下：

- **单次独立留出：** 有足够未见母体且训练资产可追溯时使用。开发组和正式评估组都不能进入生成器或评分器的训练。
- **预先冻结的五折 OOF：** 每个分子式只在一个外层测试折出现；该折的所有生成器、评分器、标准化和调参均只用另外四折及其内部开发分组。
- **探索性重评：** 若切分或过去暴露无法隔离，仍可运行算法排查，但结果不能触发本文的正式 `GO_V1b`。

五折只产生每个母体一次外层预测。不同折的训练集重叠；五个折不是五个独立实验。本文件附带的数值功效声明针对单次独立留出的工作模型。OOF 可用于扩大探索性筛查，或在另行规划训练依赖后承担推进判断，不能自动继承同一个 80% 保证；仅写“条件于已拟合检查点”不足以消除这种依赖。[8]

### 3.3 B0 不能先被训练弱化

**不能直接用原 M0 检查点作参照。** 原 M0 的 B 在官方训练集上训练；V1a 的开发与正式母体只能从这个训练集里留出（除非只用官方验证集那 33 个母体），所以原 M0 B 见过它们，且训练数据比新模型多约三分之一。用它作参照，新 B0 很可能被误判为退化。

因此先按 M0 已审计的配置，在 **V1a 的训练切分** 上重训一个单时间联合模型，记 `B_M0re`（训练 seed 0，约 0.5 GPU 小时）。这样参照与新 B0 只差“单时间→双时间”一项。在固定开发查询、固定采样噪声和相同计算口径上比较：

- `B_M0re`，同步路径；
- 新双时间 B0（训练 seed 0），同步路径；
- 新双时间 B0（训练 seed 0），候选事件领先路径。

报告联合参考匹配、合法事件率、不同事件数和每候选网络调用成本。若新 B0 的同步联合召回点估计比 `B_M0re` 低超过 0.05，或合法率低超过 0.10，先检查训练暴露、时间输入、时钟乘数、模型容量和解码器。原 M0 检查点在官方验证集上的结果可作背景报告，不参与该阈值。

这些是定位实现与训练问题的开发阈值，不是证明等效的统计检验。样本过小或区间过宽时注明。不能因为 B0 弱而宣称 B1−B0 的大差值证明 H1。

若独立时间训练导致同步覆盖不足，允许一次预先记录的开发修复：50% 批次使用 t_b=t_x，50% 使用独立 t_b/t_x，重新训练并复核。该混合策略必须在正式冻结前确定。不能在正式结果出来后替换 B0 检查点而保留 B1。

## 4. 任务 1：冻结母体、参考目录和代理定义

**输入：** 经核验的 T1x 记录、训练和评估分组。  
**输出：** `cohort.json`、`reference_catalog.jsonl`、`split_manifest.json`、输入白名单与匹配器。  
**完成标准：** 同一个候选无论来自哪个实验臂，得到相同的事件映射、参考匹配和代理标签。

### 4.1 四种身份

| 字段 | 定义 | 作用 |
| --- | --- | --- |
| `parent_id` | 元素标注、键级、电荷和多重度确定的反应物图身份 | 母体配对与宏平均 |
| `query_id` | parent＋固定反应物几何＋原子映射 | 生成输入和噪声寻址 |
| `split_group` | 分子式，包含电荷/多重度的必要区分 | 切分与聚类 |
| `reference_id` | 具体方向、R、P、参考 TS、能量和来源记录 | RMSD 匹配与能量绑定 |

同图不同构象可以属于同一个 parent，但必须保留不同参考记录和构象标识。一个母体默认只选一个查询；不能把多个构象当成更多独立母体增加 n。

### 4.2 目录建立步骤

1. 在给定分子式、总电荷和多重度内，用反应物图建立 parent。
2. 将每条反应统一到“输入 R→输出 P”的方向。反向反应若进入任务，需要完整反转事件并重算参考能量差。
3. 以有向键级差定义事件。只记录无向成断键集合会遗漏单/双键变化和方向。
4. 对反应物自同构取商得到 channel_id。原子置换必须保留元素、反应物键级与必要的立体信息。
5. 保留同事件下所有合格参考 TS 构象。不要只留一个最低记录后假装其他结构不存在。
6. 原始参考数据缺失、明显单位异常、R/P 原子映射无法解决时，标记排除原因。
7. 排除规则应用于所有臂运行前；不以“参考难命中”作为事后删母体的理由。
8. 数出不同 channel_id，K≥2 的 parent 进入候选队列；不设 K≤4 上限。

去重只能使用反应物允许的自同构。不能为了让一个候选命中，单独置换 TS 原子而破坏它和反应物/事件的对应。

### 4.3 查询锚点与统一参考能量

本轮默认从该 parent 可用的 T1x 反应物构象中，按原生电子能量最小、再按 reference_id 打破平局的规则选查询锚点。规则只执行一次，所有臂共用同一 R 坐标。

对每个具体参考记录 r 保存两种量：

\[
B^{native}_r=E^{T1x}_{TS,r}-E^{T1x}_{R,r},
\]

\[
B^{cat}_{p,r}=E^{T1x}_{TS,r}-E^{T1x}_{R,anchor(p)}.
\]

主目录排序使用共同锚点的 \(B^{cat}_{p,r}\)。它是在一致电子能量零点上的目录量，不自动等于从锚点构象动力学可达的活化势垒。`B_native` 保留用于追溯；不得混合两列计算同一个最优通道。

反应物与参考 TS 的数据来源、方法、能量类型必须一致。本文主代理使用电子能量；不把 ZPE、自由能或不同软件重新优化后的能量混进去。V1b 重新计算的 H 层能量另存。

### 4.4 联合代理匹配

候选 c 与参考记录 r 匹配，当且仅当：

1. 候选末端事件合法解码，且不是 fallback；
2. 存在同一个允许的反应物原子置换 π，使有向键级事件一致；
3. 在该 π 下，对 TS 坐标只做平移与真旋转 Kabsch，全原子 RMSD≤0.50 Å；
4. 原子数、元素、电荷和多重度一致。

默认采用全原子 RMSD。若仓库原有指标用重原子，先实现并冻结两列，主列仍按本节执行；不能直接借用一个名称相同而原子集不同的函数。镜像变换不允许。

\[
{\cal M}(c)=\{r:\mathrm{event\_match}(c,r)
\land \mathrm{RMSD}_{\pi}(x_c,x_r)\le0.50\ \mathrm{\AA}\}.
\]

当 \({\cal M}(c)\neq\varnothing\) 时，候选携带的代理势垒为：

\[
\widetilde B(c)=\min_{r\in{\cal M}(c)} B^{cat}_{p,r}.
\]

**只能从实际匹配的参考记录取得能量。** 一个候选如果只接近同事件的高势垒 TS 构象，不能借用这个事件下另一个没有匹配到的低势垒构象。

### 4.5 主召回目标与近最优目标

定义该 parent 的最低目录势垒 \(B^{cat,*}_p\)。主目标记录集合为：

\[
{\cal R}^{*}_p=\{r:B^{cat}_{p,r}\le B^{cat,*}_p+\varepsilon_{tie}\},
\]

其中 `epsilon_tie_kcal=0.000001`，仅用于浮点并列处理。主命中要求 \({\cal M}(c)\cap{\cal R}^{*}_p\neq\varnothing\)。

这样主指标的全称是“最低已知参考通道的事件＋结构联合召回”。另报：

- 事件级最佳通道 AUC：只看候选事件是否属于最低目录势垒事件，忽略结构，按第 9.1 节同样的预算点与权重计算。它是必报的关键次要指标，用于判断收益是否停留在事件层而没有转化为可匹配几何（第 6.6 节），但不作为第二个闸门。
- 近最优联合召回：目录参考势垒在最低值＋2 kcal/mol 内。
- 全目录不同事件覆盖：有限目录的覆盖率。
- 未匹配率：包括未知事件、已知事件但几何不匹配两种不同情况。

`0.50 Å`、`2 kcal/mol` 和数值并列容差都是本轮固定的评估选择，不是 DFT 误差上界。

### 4.6 为什么不声称保守地低估 B1

未匹配候选可能是新低势垒通道，也可能是错误事件或坏几何。不同方法的未匹配率、真实有效率和目录覆盖偏差可以不同。因此：

- 代理结果不能证明新通道不存在；
- 代理差值可能偏向任一臂；
- “不计新通道”不保证 B1−A2 是真实差值的下界；
- 未匹配候选应保留给 V1b 的概率抽样，不能在 V1a 删除。

若 B1 的未知事件比例上升，报告这是需要认证的变化，不提前写成创新发现，也不直接写成失败。

## 5. 任务 2：训练可比较的生成器与 DFT 目录势垒头

**输入：** 每个外层折的训练清单、开发清单和可复用检查点。  
**输出：** g/h/f、h_E/h_X、训练标签清单、开发校准报告。  
**完成标准：** 模型没有见过正式组；A2 与 B1 的评分输入都在训练覆盖内；真实 rollout 上存在可利用的分数信号。

### 5.1 生成器保持的结构与训练规格

- 保留连续、对称、电子数守恒的 BE 矩阵，只有末端解码写入整数事件。
- 保留 M0 的等变骨干。双时间 f 默认 6 层，128 标量/32 向量通道；A 的 g/h 合计参数与 f 相差不超过 5%。
- 每个生成角色默认 60,000 次更新，batch size、优化器、EMA 和噪声从已审计的 M0 配置继承。
- 不把 M0 的单时间检查点当作支持整个 [0,1]² 的模型。新双时间输入需要对应训练。
- 训练 seeds 为 0、1、2：A 的 g、h 与 B 的 f 各训练三份，第 k 份 A 与第 k 份 B 配对评估；采样只用 seed 0。任何一臂都不能独享更多训练副本，也不能事后挑选表现好的训练 seed。
- 势垒头 h_E/h_X 只依赖训练切分，不依赖生成器 seed；三个训练 seed 共享同一组评分器成员，保证 A2/B1 在每个 seed 下仍使用同一评分。
- 另按第 3.3 节在同一切分上重训单时间联合模型 `B_M0re`（训练 seed 0），只用于基线复核，不进入效率比较。
- 只比较同步路径和一个温和事件领先路径，开发后冻结一个正式路径。不得把正式集当作时间调度搜索器。

生成器训练默认保持 M0 的每条记录原生 R 输入视图，g/h/f 必须一致；正式评估才按第 4 节给每母体固定一个查询锚点。h_E/h_X 的插值也使用相同训练记录输入，而其能量标签统一到训练母体的目录锚点零点。输入几何和能量零点是不同概念。若改成所有训练反应共用母体锚点几何，三种生成角色须一起改，旧视图检查点不得假装已按新视图训练。

### 5.2 两时钟训练与积分

训练样本的噪声和目标沿用 M0：

\[
b_0=b_R+\sigma_b\epsilon_b,\qquad
x_0=x_R+\sigma_x\epsilon_x,
\]

\[
b_{t_b}=(1-t_b)b_0+t_b b_P,\qquad
x_{t_x}=(1-t_x)x_0+t_xx_{TS}.
\]

事件速度目标为 \(b_P-b_0\)，几何速度目标为 \(x_{TS}-x_0\)。两个时间嵌入分别进入模型；速度输出不预先乘采样路径导数。

| 路径 | t_b(s) | t_x(s) | 说明 |
| --- | --- | --- | --- |
| `sync` | s | s | B0 与 M0 对照必跑 |
| `event_lead2` | s | s² | 唯一可开发选择的事件领先路径 |

积分必须使用相邻网格的实际时钟差：

```python
import numpy as np

def clock_grid(path, n_steps=50):
    s = np.linspace(0.0, 1.0, n_steps + 1)
    if path == "sync":
        tb, tx = s, s
    elif path == "event_lead2":
        tb, tx = s, s * s
    else:
        raise ValueError(path)
    return tb, tx

def observation_index(clock, target):
    if not (0.0 <= target <= 1.0):
        raise ValueError("target outside [0,1]")
    idx = int(np.searchsorted(clock, target, side="left"))
    return min(idx, len(clock) - 1)

def increments(path, n_steps=50):
    tb, tx = clock_grid(path, n_steps)
    return np.diff(tb), np.diff(tx)
```

每一步先用同一旧状态计算两个速度，再分别乘 Δt_b、Δt_x 更新。不能先更新 b，再用新 b 计算同一步的 x 速度。`sum(Δt_b)=sum(Δt_x)=1` 必须通过测试。

观察点按网格向上对齐，记录请求时间、实际时间和 step_index。不得把不存在于离散网格上的 0.45 写成实际干预时刻。

### 5.3 势垒头改用 T1x 训练折内标签

V1a 默认 h_E/h_X 预测 **目标参考记录相对于该母体锚点的目录电子势垒**。标签是第 4.3 节的 \(B^{cat}_{p,r}\)，来自训练折已有 T1x DFT 能量，不依赖先跑 640 条 xTB 验证链。

对一条训练反应，沿生成任务的插值状态监督最终目标记录的目录势垒：

\[
h_X(R,b_{t_b},x_{t_x},t_b,t_x)\longrightarrow B^{cat}_{p,r}.
\]

这个标签不是插值坐标的真实势能。模型也不是一个具有可信力场导数的势能面。输入梯度只作为引导方向，需要用真实生成轨迹验证其用途。

不得把一个未匹配生成候选的“本母体最低参考势垒”贴给它当回归真值。模型生成了不同事件时，原训练反应的标签不自动跟随到这个新事件。

### 5.4 h_E 与 h_X 的数据覆盖

| 头 | 允许输入 | 训练状态 |
| --- | --- | --- |
| h_E | R、当前 b、t_b；可使用输入 R 几何 | 插值事件、合法终点事件 |
| h_X | R、当前 b/x、t_b/t_x | 双时间插值、串联边界、终点 |
| 二者均禁止 | 正式参考 ID、正式目录势垒、已知 K、真实 P/TS 的额外旁路 | — |

h_X 每个训练 batch 的来源混合固定为：

- 50%：双时间插值，t_b、t_x 独立抽样；
- 25%：串联几何边界，t_b=1、b=b_P，t_x 随机；
- 25%：接近终点的状态；其中一半取精确终点，一半取两个时间在 [0.8,1] 的插值。

每个来源内先均匀抽 parent，再均匀抽该 parent 的反应记录，再抽噪声和时间。避免高 K 母体和路径帧数多的反应支配损失。

这些插值属于生成流的监督构造，不要求读取 T1x 全部 NEB 中间帧。若增加原始路径帧训练，必须为其准确区分“该帧真实势能”和“终点目录势垒”两种目标，不能混入同一回归列。

### 5.5 模型规模、损失与标准化

默认每种头采用 3 层、64 标量/16 向量通道的 M0 式骨干，masked pooling 输出一个标量。每种头训练三个成员，初始化 seeds=101/102/103，每成员默认 20,000 步。开发期若算力不足，先报告总开销，不把少训练一个臂的评分器作为省钱方案。

标准化只用当前外层训练折：

\[
y=\frac{B^{cat}-m_{train}}{s_{train}},
\qquad
s_{train}=\max(\mathrm{IQR}_{train},5\ {\rm kcal/mol}).
\]

损失用 Huber 回归；可固定加入 0.2 权重的同母体不同事件排序损失。排序对只从训练折抽取，标签差至少 2 kcal/mol。所有 loss 权重在正式冻结前确定。

三个成员的分散不是经过校准的置信区间，只是分数可靠性诊断。报告单成员和集成校准，不写“集成一致，因此物理正确”。

损失函数使用标准化目标，在线 h_E/h_X 接口则先对每个成员执行 `B_hat = y_hat * s_train + m_train`，返回 kcal/mol。第 5.6 节的 μ_B、σ_B 指反标准化后的均值与分散；不能把标准化输出再次当作原始势垒归一化。

### 5.6 默认搜索分数取消 p_success 分支

旧 V1 的 `p<0.5` 分支可能使大部分引导实际上只推动 xTB 优化成功。V1a 不训练量化成功率头，默认分数为：

\[
\Phi =
\frac{\mu_B-m_{train}}{s_{train}}
+0.25\,\mathrm{clip}\left(\frac{\sigma_B}{s_{train}},0,2\right).
\]

分数越低越好。归一化参数在训练折确定，A2 与 B1 完全共享。不额外引入“低概率时沿 log p”的隐藏路径。

开发期用真实 rollout 分数分布冻结可用范围，例如预测势垒的训练 1%–99% 分位数外扩 10 kcal/mol、成员分散上限。超出可用范围的指导步跳过，保留原因；不能悄悄用一个未经校准的巨大负势垒继续推进。

跳过引导不等于候选化学失败。该候选可以按原生成器继续，并正常计费、解码和代理评估。非有限状态、非有限模型输出则是数值失败，单独终止并记账。

### 5.8 真实 rollout 校准

教师插值上的 MAE 不够。开发集至少执行：

1. A0、A2、B0、B1 的真实前向轨迹；
2. 在预设几何时间点保存分数、分散、梯度范数；
3. 冻结轨迹后离线匹配末端参考，给匹配轨迹关联其实际匹配的目录势垒；
4. 对未知事件、已知事件但结构不匹配、合法匹配分别报告样本数；
5. 比较分数能否在同母体内排序最终可匹配通道；不把未匹配样本伪造为高势垒；
6. 用固定噪声的一次评分方向脉冲与等幅随机脉冲，验证分数下降是否对应目录效用改善。

必须显示校准的选择偏差：只有匹配轨迹才有目录势垒标签。因此“匹配子集 MAE 很低”不保证所有生成状态都在支持范围内。

最低可用条件是开发集存在“评分相关信号＋有效事件可改”的重叠窗口。若终点排序有用，但事件早已锁定，只能说明适合后筛选；不能作为 H1 的窗口证据。

### 5.9 评分不可用时的有限修复

允许在开发数据上定位一次具体问题：

- 串联边界缺样本：补足第 5.4 节固定混合。
- 单位、反向势垒或锚点错误：修标签并重训。
- 初期状态不可识别：收窄引导时间窗，不把这个阶段的低准确率当模型坏掉。
- 非有限梯度或明显离分布：修正数值与位移限制。
- 有真实分数变化但事件不变：转入窗口诊断。

修复后重新冻结全部依赖配置。若仍没有可靠信号，返回 `HOLD_SCORE`。此时不启动 DFT“碰碰运气”，也不写 H1 被证伪。

## 6. 任务 3A：连续几何引导与完整事件回放

**输入：** 冻结的生成器、h_E/h_X、两个时钟和开发选定的强度。  
**输出：** 一份共享引导实现、B2 回放实现、配对完整性测试。  
**完成标准：** 干预只直接进入 x，后续 b 的变化来自耦合模型；切断控制真正回放整个 b 轨迹。

### 6.1 位移归一化

对 h_X 的输入几何求导，先去几何中心，再以每原子向量 RMS 归一化：

\[
g_x=P_{COM}\nabla_x\Phi,\quad
\delta x=-\alpha_x\Delta t_x
\frac{g_x}{\sqrt{N^{-1}\sum_i\|g_{x,i}\|^2}+\epsilon}.
\]

α_x 的单位是 Å/单位几何时钟。默认开发网格为 {0.15,0.30}，另有 α=0 校验。总位移随实际 Δt_x 缩放，不能因为步数翻倍就获得双倍引导量。

每步 RMS 不超过 α_xΔt_x，单原子位移不超过其 3 倍。若需要收缩以满足单原子上限，评分与随机脉冲的匹配幅度按实际收缩后的值处理。

### 6.2 共享实现规格

```python
import torch

def centered(v, mask):
    m = mask.to(v.dtype)[..., None]
    n = m.sum(dim=1, keepdim=True).clamp_min(1.0)
    return (v - (v * m).sum(dim=1, keepdim=True) / n) * m

def rms_atom(v, mask):
    n = mask.sum(dim=1).clamp_min(1).to(v.dtype)
    return ((v.square().sum(dim=-1) * mask).sum(dim=1) / n).sqrt()

def unit_geometry_direction(gradient, mask, eps=1e-10):
    g = centered(gradient, mask)
    size = rms_atom(g, mask)
    valid = size > eps
    unit = -g / size.clamp_min(eps)[:, None, None]
    return torch.where(valid[:, None, None], unit, torch.zeros_like(unit)), valid

def score_direction(score_fn, query, state):
    with torch.enable_grad():
        x = state.x.detach().clone().requires_grad_(True)
        phi = score_fn(query, state.b.detach(), x, state.t_b, state.t_x)
        if not torch.isfinite(phi).all():
            raise FloatingPointError("nonfinite score")
        grad = torch.autograd.grad(phi.sum(), x, create_graph=False)[0]
    if not torch.isfinite(grad).all():
        raise FloatingPointError("nonfinite gradient")
    return unit_geometry_direction(grad.detach(), query.atom_mask)
```

生产代码在外层使用 no_grad，局部重新打开输入梯度；不要把引导代码包在不可撤销的 inference_mode 下。每步后 detach，评分器和生成器参数均冻结。

A1 对 b 的梯度先对称化并投影到完整有效 BE 矩阵的零和空间，再归一化，默认 α_b∈{0.10,0.25}。不沿整数解码器反传。

### 6.3 同步更新顺序

每个步骤使用旧状态：

1. 读取旧 b、x、t_b、t_x；
2. 生成器输出两个速度；
3. h_X 对旧 x 求输入梯度；
4. 同时生成 b_next 和 x_next；
5. 执行必要的守恒投影、去中心与 mask 检查；
6. 写入快照和已消耗成本。

同一步的几何脉冲不应直接瞬间修改 b；它在随后的模型调用中影响事件速度。若代码在脉冲后直接替换成更有利的解码事件，这不属于 H1。

### 6.4 B2 回放完整无引导 b 轨迹

对同一 query/seed/proposal：

- 先生成无引导 B0，保存每步 b_k 和时间网格；
- B1 从相同 b_0/x_0 出发，正常耦合更新并施加几何引导；
- B2 从相同起点出发，x 保持 live，由当前回放 b_k 与自身 x_k 计算几何速度；
- B2 的下一步 b 强制赋值为 B0 的 b_{k+1}，不能使用其 live 事件速度；
- B2 接收与 B1 相同的引导函数、强度与激活时间。

只把 b.detach() 传给评分器并没有切断前向耦合；那只是阻止梯度回传。B2 必须回放完整事件轨迹。

### 6.5 不可省略的配对测试

- α=0 时，B0、B1、B2 的 b/x/解码结果在预设容差内一致。
- B2 每一步 b 与 shadow 逐元素一致，shadow 不被原地修改。
- 无脉冲 F0 与回放 C0 一致。
- 正常 B1 的 x 干预之后，若 b 改变，变化出现在后续模型步骤。
- 增加日志、评分调用、随机方向数，不改变其他候选初始噪声。
- 相同 query/seed/proposal 在不同分批方式下按已有确定性规格复现；GPU 非确定性容差明确记录。
- fallback 状态不会被“与 B0 相同”覆盖为成功。

### 6.6 开发期引导漂移检查

引导梯度来自势垒回归器，并不指向参考 TS。主终点要求参考 RMSD≤0.50 Å；而 α_x=0.30、引导区间跨 Δt_x≈0.5 时，累计引导位移最多可达约 0.15 Å RMS，与 M0 命中候选的中位 RMSD（约 0.2 Å）同量级。若引导系统性抬高 RMSD，事件层收益会被几何匹配率下降抵消，主比较测到的就不再只是通道选择。

开发集上，用候选的路径与强度执行：

1. 取 B1 与 B0 共享起点、最终事件相同且属于目录事件的配对；
2. 在同一合法原子映射下，比较二者到最近同事件参考的 RMSD 差和联合匹配率差；
3. A2 的固定事件几何阶段同样与“同事件、无引导几何”配对比较；
4. 若任一臂中位 RMSD 增加超过 0.05 Å，或联合匹配率下降超过 0.05，按预设顺序把引导结束时刻 `t_x,stop` 从 0.95 提前到 0.85、再到 0.75，取第一个两臂都满足阈值的值；
5. A2 与 B1 使用同一个 `t_x,stop`；三档都不满足时保留 0.75，并在报告中把引导漂移列为主终点的已知稀释来源。

这些是开发期定位阈值，不是等效检验。检查只用开发集；正式集不再调整 `t_x,stop`。

**解释规则。** 正式结果中若事件级最佳通道 AUC 差为正、而联合 AUC 差不为正，报告为“事件层收益未转化为可匹配几何”。这不改变第 10 节的闸门决策，但应作为下一轮修改引导目标或结束时刻的依据。


## 7. 任务 3B：三幅度配对脉冲与唯一机制闸门

**输入：** 开发阶段选定的时间窗、冻结的 h_X、完整回放实现。  
**输出：** 每个母体的机制摘要、逐配对事件转移、幅度响应曲线。  
**完成标准：** 有一个明确的机制闸门，要求评分方向同时胜过“不推”和“随机推”，从而排除“评分方向只是比随机方向破坏得少”的误读，且不被结果噪声系统性拉低。

### 7.1 开发扫描与正式确认分开

开发阶段在 t_x∈{0.20,0.35,0.50,0.65,0.80} 的对齐网格处扫描。每个时刻同时检查：

- 评分在真实 rollout 上是否有相关信号；
- 事件是否仍能在有效解码条件下改变；
- 几何扰动是否落在预定信赖范围；
- 干预是否主要增加无效状态或未知事件。

从这五个点中选一个 t* 作为正式脉冲时刻，并冻结连续引导区间。默认先选“有可靠评分且尚有事件响应的最早时刻”，同分时按较小实际 step_index。只有开发数据可参与选择。

正式机制分析不在五个时刻里选最大的结果。若开发扫描全无重叠，先返回 HOLD_SCORE 或当前配置的窗口问题，不启动大规模正式采样。

### 7.2 每个起点的分支

所有正式母体各取 8 个 proposal，在 3 个训练 seed 的模型上各运行一次（采样 seed 0）。起点使用 `mechanism` 随机数命名空间，与罕见度探查和效率运行分开。

| 分支 | 脉冲 | 后续事件 | 后续几何 |
| --- | --- | --- | --- |
| F0 | 无 | live | 无持续引导 |
| F_S(a) | 评分下降方向，幅度 a | live | 无持续引导 |
| F_R(a) | 固定随机方向，同实际幅度 | live | 无持续引导 |
| C_S(a) | 与 F_S 相同 | 完整回放 F0 的 b | live，无持续引导 |
| C0 | 无 | 回放 F0 的 b | 与 F0 一致，作为实现检查 |
| B1_cont | 冻结连续引导 | live | 连续引导 |
| B2_cont | 与 B1_cont 相同 | 回放 F0 的 b | 连续引导 |

a∈{0.05,0.10,0.20} Å，定义为全原子位移 RMS。三个幅度各自只配一个预先寻址的随机方向；默认同一起点三个幅度共享同一个随机单位方向以减少幅度比较噪声。不能多抽随机方向，再挑最差的作为对照。

C0=F0，不需要额外算一条；无引导 shadow 的完整轨迹仅计算一次。C_S 不是主效率臂。

### 7.3 严格等幅与失败处理

评分方向和随机方向都在相同原子 mask 下去中心、归一化并使用相同单原子上限。若任一方向触发单原子上限，两个方向统一缩到共同可行的 RMS 幅度。

记录 `requested_rms` 与 `actual_rms`。不能评分方向实际移动 0.20 Å、随机方向实际只移动 0.06 Å，却称为“等幅对照”。

梯度为零、超出冻结支持区间或不能构造合法脉冲时：

- 记录 `PULSE_NOT_APPLICABLE` 及原因；
- 为主机制的全计划母体平均保留零干预结果，不删除该起点提高均值；
- 可用覆盖率另报；
- 如果覆盖不足以解释无响应，不能触发窗口 NO-GO。

数值错误或非有限输出不是合法零干预。暂停对应配对并修复实现；不能将配对的一侧失败悄悄变成另一侧的成功样本。

### 7.4 已知事件效用

机制量要直接看事件分布，而不是只看几何 RMSD。对有效事件 e：

\[
B^{cat}_{p,e}=\min_{r:\,channel(r)=e} B^{cat}_{p,r},
\]

\[
U_p(e)=
\begin{cases}
\max\{0,1-(B^{cat}_{p,e}-B^{cat,*}_p)/10\}, & e\in K_p,\\
0, & e\notin K_p\ \text{或事件无效}.
\end{cases}
\]

势垒单位为 kcal/mol。分母 10 是固定的效用尺度，使近低势垒事件也贡献信号；它不是温度、Boltzmann 因子或真实速率关系。

这里 U 只衡量生成事件在已知目录中的潜在价值，允许使用该事件的最低目录记录。它不为当前几何赋予势垒，也不替代第 4 节要求实际结构匹配的效率指标。两种定义必须保持不同字段名。

未知事件 U=0 只是有限目录评分约定。不能据此声称未知事件的真实势垒更高。

### 7.5 机制闸门：两个对比的交并检验

对每个 parent/训练 seed s/proposal j/幅度 a，定义两个配对差：

\[
m^{(0)}_{p,s,j,a}=U(F_S(a))-U(F0),\qquad
m^{(R)}_{p,s,j,a}=U(F_S(a))-U(F_R(a)).
\]

先在母体内等权平均 3 个训练 seed、8 个 proposal、3 档幅度：

\[
m^{(0)}_p=\frac1{3\times8\times3}\sum_{s,j,a}m^{(0)}_{p,s,j,a},\qquad
M_0=\frac1P\sum_p m^{(0)}_p,
\]

M_R、m^{(R)}_p 同理。两项分别用第 9.2 节的分子式聚类函数求单侧 95% 界限。

**机制通过** 要求 \(L(M_0)>0\) 且 \(L(M_R)>0\)：评分方向平均既胜过不干预，也胜过等幅随机方向。这是交并检验（intersection–union test），两项各在 α=0.05 下检验，整体错误推进率不超过 0.05，不需要多重比较校正。**机制停止** 在 \(U(M_0)<0.02\) 或 \(U(M_R)<0.02\) 时触发：只要有一项已排除有用幅度，就不再投入当前配置。

“评分方向比随机方向破坏得少、但仍不如不推”的情形会使 M_0 下界不大于 0，因此不能通过机制闸门。这保留了 v2.0 想要的保护，但不再逐对取最大值。

**为什么删除 v2.0 的逐对 max。** v2.0 定义 \(m=U(F_S)-\max\{U(F0),U(F_R)\}\)。对两个带噪结果取最大值，期望不小于各自期望中的较大者，于是随机脉冲碰巧落到更好事件的“好运气”全部记到对照一侧，m 的期望系统性偏负，且偏差随脉冲改变事件的频率增大。简单模拟（脉冲以概率 q 改变事件；新事件落入已知通道的概率随机方向为 0.5、评分方向为 p_S；落入已知通道时效用在 0–1 均匀分布，否则为 0）：

| q | p_S | E[U_S−U_0] | E[U_S−U_R] | v2.0 的 E[m] |
| ---: | ---: | ---: | ---: | ---: |
| 0.2 | 0.5（无方向性） | 0.000 | 0.000 | −0.033 |
| 0.2 | 0.7 | +0.020 | +0.020 | −0.014 |
| 0.4 | 0.7 | +0.040 | +0.040 | −0.026 |

第二行两个对比恰为规划目标 +0.02，v2.0 的 M 真值却为负，会以高概率触发机制停止。0.20 Å 档随机脉冲改变事件最频繁，偏差最大。模拟见 `v1a_gate_power_v21.py` 的 `max_metric_bias`，它是说明性工作模型，不是 xtbflow 实测。

M_0、M_R 未通过，不证明评分方向在所有意义上都无益；只说明在本配置和本精度下未获得足以推进的证据。

**机制规划目标：M_0=M_R=+0.02。** 这是设计的可识别效应。两项共享 U(F_S)，通常正相关；开发集必须按上述定义分别估计两项的母体级 SD、组内相关和二者相关，不能沿用 v2.0 单一 M 的方差。

### 7.6 机制必须展示的解释量

解释量不再分别设置显著性闸门：

- M_0、M_R 按幅度分档的均值与区间（主检验已对三档等权平均，分档只作解释，不挑最有利一档）；
- 有益改写、无益改写、有害改写和事件不变的比例；
- 已知→已知、已知→未知、未知→已知、有效→无效的转移；
- 每档幅度的请求值、实际值、可用覆盖与事件改变率；
- C_S 的事件与 F0 是否逐条一致；
- 持续引导 B1_cont−B2_cont 的联合代理命中与事件效用；
- 几何改善而事件不变的占比。

只用事件效用时，C_S=F0 是回放构造的结果，不是新的独立统计证据。持续 B1/B2 的联合命中差用于检验该事件反馈是否转化成可匹配几何；若出现明确矛盾，在结果中限制 H1 解释，而不是隐藏控制结果。

### 7.7 三档无响应何时允许停止

`NO_GO_WINDOW_THIS_CONFIG` 只在正式统计未给出 GO 后，用作不推进的诊断原因；不能提前截断已经规划的统计 GO。它仅可在全部条件具备时给出：

1. 当前评分器在该冻结时刻有开发验证的信号，正式支持覆盖没有明显塌陷；
2. 三档请求幅度均实际达到可比较的位移；若 0.20 Å 因约束只执行了 0.03 Å，不能说已经测试 0.20 Å；
3. 对每档评分与随机脉冲，先在母体内平均，再保留分子式聚类估计事件改变率；其单侧 95% 上界均小于预设 `delta_event_response=0.02`；
4. 未把 invalid、未知映射或未执行的起点删除后计算改变率；
5. 回放和配对测试全部正确。

事件改变率按“相同合法事件身份是否改变”统计，同时显示有效→无效。若大幅度主要把事件推成非法状态，结论是干预不稳定；不是没有可改写窗口。

如果随机脉冲明显改动事件，只有评分方向不响应，则归因于当前评分方向，不归因于“事件不可改变”。若两者都有响应但 M_0、M_R 不改善，则是方向效用不足。

全部零改变时，不能用 sandwich 标准误为 0 得出上界为 0。使用在开发期冻结的有界聚类模型求保守上界；无法获得可靠上界时标记 `WINDOW_PRECISION_UNRESOLVED`，不能触发本项停止。不能将 P×24 个起点当成独立二项样本来制造很窄的上界。

这个停止结论只覆盖已经测试的模型、时间路径、t* 和幅度范围。它不证明所有时刻、任意强度或其他形式的反馈都无效。

### 7.8 机制工作量

设正式母体 P，3 个训练 seed，8 个起点，1 个正式时刻。每个起点的 F0＋3×{F_S,F_R,C_S} 共 10 个终局分支：

\[
N_{\rm pulse}=P\times3\times8\times10.
\]

P=300 时为 72,000 个终局分支。连续 B1/B2 另有 14,400 个分支，总计最多 86,400 个终局结果；完全相同的 F0/C0 不重复计算。

这些是逻辑终局数，不是 86,400 次从零完整采样。共享前缀只执行一次，之后续跑分支。预算必须用真实分支续跑计时估算，不能把 8 个 proposal 当成只有 8 次梯度求值。

开发阶段若扫描五个时刻，另计开发工作量。正式阶段不把五时刻全部加入主机制而仍声称同一预算。

## 8. 任务 4：同一生成流上的公平成本曲线

**输入：** 冻结模型、评分器、调度规则、网络调用成本表与全局预算。  
**输出：** 五臂候选流、完整操作成本、五个预算前缀、独立罕见度分层。  
**完成标准：** 比较的是相同资源下的已完成候选集合，A2 没有因不合理首轮调度或批处理效率被人为削弱。

### 8.1 B0 等效候选：按网络调用计数

**为什么不用 GPU 墙钟。** A2 是“提议、剪枝、再提议”的小批次串行流程，B0/B1 可以大批并行。按实测 GPU 时间记账，A2 会因批处理效率吃亏，比较的就成了实现而不是算法；在批处理中给每个候选分摊“完成时刻”也难以复现。因此主比较按网络调用计数，GPU 墙钟只作次要报告。

**成本表。** 以同一分子上联合网络 f 的一次前向为 1 个单位，在开发期一次性测定并冻结下表（按原子数分箱）：

| 调用 | 单位成本 |
| --- | --- |
| f 前向 | 1 |
| g 前向、h 前向 | `w_g(N)`、`w_h(N)` |
| h_E、h_X 单成员前向 | `w_E(N)`、`w_X(N)`；三成员集成计 3 倍 |
| h_X 对输入几何的反向 | `w_X_back(N)`，按成员计 |
| A1 对 b 的评分反向 | `w_E_back(N)`，按成员计 |

测定方法二选一，冻结前固定：在所有网络都能使用的同一大批量下测每分子 GPU 时间并相对 f 归一化；或用 profiler 统计每分子乘加次数。冻结后，任何实际批大小、设备负载或并行方式都不再改变记账。

**预算点。** B0 完成一个候选需要 50 次 f 前向，即 50 个单位。预算点定义为

\[
C(k)=50k\ \text{单位},\qquad k\in\{4,8,16,32,64\},
\]

称为“k 个 B0 等效候选”。不同母体之间的规模差异已体现在成本表的原子数分箱中；宏平均仍每母体等权。报告中同时显示各臂在每个预算点实际完成的候选数，防止把“等效 16”误读成 16 个候选。

解码、图规范化、去重、匹配等 CPU 工作单列，不换算进主预算。GPU 墙钟按批记录、按臂汇总，作次要报告。

### 8.2 逻辑执行顺序与前缀

每个（母体，训练 seed，臂）的算法定义为一个**逻辑顺序程序**，成本按这个顺序累计；物理执行可以跨母体、跨候选任意分批，但每次调用都记到它在逻辑顺序中的位置。

- A0/A1/B0/B1：候选按 proposal_id 顺序逻辑生成，候选完成成本等于其最后一步完成时的累计单位。
- A2：每轮内按阶段广度优先、阶段内按 proposal_id 排序（事件生成 → 第一段几何 → 评分晋级 → 第二段几何 → 评分晋级 → 完成），候选完成成本等于其最后一步几何完成时的累计单位。
- 引导步额外计入评分前向和输入反向；被淘汰的部分几何、非法提议和失败照常计费。

离线从最大预算的流截取：

\[
{\cal C}_{p,a,s}(k)=
\{c:\mathrm{completion\_units}(c)\le C(k)\}.
\]

只有实际完成的候选进入召回。由于单位成本确定，调度器在启动下一原子任务前可以精确判断是否会越过最大预算；越过则不启动，不存在尾部超支。不能事后把未完成候选算进结果。

### 8.3 A2 固定“首轮 4，后续 8”

A2 使用简单的小轮次策略：

1. 首轮提议 4 个事件，各自解码；非法提议计费并占已发生的提议。
2. 合法事件各自展开几何到第一个冻结时点。优先保留 2 个最佳，加 1 个来自其余候选的随机探索项。
3. 展开到第二个时点，保留 1 个最佳，加 1 个随机探索项。
4. 将存活项完整生成，得到早期可用候选。
5. 之后每轮提议 8 个，按旧版 4 最佳＋1 随机，再 2 最佳＋1 随机晋级。
6. 新轮次重复直到最大预算耗尽；每个固定事件下可使用与 B1 相同的 h_X 几何引导。
7. 没有足够合法项时保留全部，不补造成功项；下一轮照常使用新 proposal_id。

几何时点只允许开发选择一套，例如 {0.40,0.70} 或 {0.60,0.85}。所有预算点采用同一套被冻结的时点和首轮规则。A2 看不到 K、最低参考通道或真实命中。

候选不足时的随机探索项不能与最佳项重复。随机抽取只依赖固定排序后的候选 ID 与专用随机流，不能受日志调用顺序影响。

### 8.4 候选流与成本公平

A0/A1/B0/B1 连续生成完整候选到最大预算。A2 的部分几何和重新提议是正式算法成本，不能只计算最终留下的几个候选。

五臂允许完成不同数量的候选。每臂都对全部完成候选离线做代理评估，无“每臂只选两个进主终点”的提名瓶颈。h_X 的终点排名留给部署解释和后续审计，不控制 V1a 哪些候选可以被评估。

若 4 单位处某臂仍无完成候选，召回为 0。开发阶段应先查这是否是人为调度障碍；正式冻结后不能按各预算点重新排程以修饰曲线。

### 8.5 可寻址随机数

使用语义键，而不是可变全局 RNG 的调用次数：

```python
import hashlib
import json

def addressed_seed(namespace, **keys):
    payload = json.dumps(
        {"namespace": namespace, **keys},
        sort_keys=True, separators=(",", ":"), ensure_ascii=False
    ).encode("utf-8")
    digest = hashlib.sha256(payload).digest()
    return int.from_bytes(digest[:8], "little") % (2**63 - 1)
```

至少区分：

| namespace | 键 |
| --- | --- |
| `training` | fold、role、training_seed |
| `efficiency` | fold、query、training_seed、sampling_seed、proposal、noise_role |
| `a2_explore` | query、training_seed、sampling_seed、round、promotion_stage |
| `mechanism` | fold、query、training_seed、sampling_seed、proposal、noise_role |
| `pulse_random` | query、training_seed、sampling_seed、proposal、t_star |
| `rarity_pilot` | fold、query、pilot_seed、proposal |
| `v1b_candidate_sample` | source_hash、stratum |
| `v1b_parent_sample` | source_hash、parent_stratum |

A0/A1/A2 的事件初始噪声在共同 proposal 索引上配对；B0/B1/B2 在共同联合起点上配对。跨架构不能完全一一对应的随机项应如实记录，不能声称完全共同随机数。不同训练 seed 使用不同噪声键，避免三份模型共用完全相同的起点而低估采样变化。

### 8.6 最优通道的先验频率分层

对每个正式 parent，用训练 seed 0 的 B0 额外生成一条无引导探查流，默认 128 个 proposals，使用 `rarity_pilot` 独立噪声。该流只用于分层，不提供候选给效率臂，不参与 A2/B1 调度。

为减少“几何难匹配”与“事件稀有”混淆，主分层频率用 **最优目录事件的出现频率**，只看合法事件；分母仍含全部计划提议，非法不从分母删除。另报事件＋几何联合频率。

默认层：

- `unseen_in_pilot`：128 次中 0 次；
- `rare`：有出现，频率≤1/32；
- `intermediate`：>1/32 且≤1/8；
- `common`：>1/8。

0/128 不表示真实概率为 0。记录二项区间和实际次数；如果母体数量不足以支持四层区间，合并显示可在冻结前规定，不能按 B1 效果挑分层边界。

B0 探查可以在正式组上进行，因为它不调参、不向方法输送标签且使用独立噪声；它也必须计入评估开销。冻结后不得因某个母体“看起来不稀有”而剔除它。

### 8.7 失败与缺失

| 状态 | 在线已花成本 | 代理召回 | 统计处理 |
| --- | --- | --- | --- |
| 合法完成、匹配参考 | 全计 | 按冻结定义 | 保留 |
| 合法完成、未匹配 | 全计 | 0 | 保留未知与几何未匹配分类 |
| 解码失败或 fallback | 全计 | 0 | 保留失败类别 |
| 算法内数值失败、到单候选上限 | 全计 | 0 | 计协议失败 |
| 正常到预算，没完成新候选 | 全计 | 没有新增命中 | 不删母体 |
| 全局机器中断、缺日志 | 已花成本保留 | 未完成，非 0 标签 | 恢复配对单元或 HOLD |
| 目录或对称匹配器无法解决 | 评估成本保留 | 未知 | 修复评估，不能默认为未命中 |

对称搜索达到内部计算上限时返回 `MATCH_UNRESOLVED`，不是 `NO_MATCH`。如果该问题影响主终点且无法恢复，本轮不能给正式 GO。

## 9. 任务 5：主指标、配对区间与功效冻结

**输入：** 开发期的母体级差值、实际分子式组、五个成本点和机制定义。  
**输出：** `power_plan.json`、最终 N、主统计函数、冻结后的一次正式分析。  
**完成标准：** 计划功效属于最终使用的指标和闸门，而不是从另一个二元模型移来的数字。

### 9.1 每个母体的 AUC

对 parent p、arm a、训练 seed s、预算 k：

\[
Y_{p,a,s}(k)=
\mathbf 1[\exists c\in{\cal C}_{p,a,s}(k):
{\cal M}(c)\cap{\cal R}^{*}_p\ne\varnothing].
\]

k=4、8、16、32、64。定义归一化 log-budget 梯形面积：

\[
A_{p,a,s}=
\frac{Y(4)+2Y(8)+2Y(16)+2Y(32)+Y(64)}8.
\]

先平均每母体三个训练 seed，再计算配对差（第 k 份 A 与第 k 份 B 配对）：

\[
d_p=\frac13\sum_{s=0}^{2}(A_{p,B1,s}-A_{p,A2,s}),
\qquad
\Delta_{\rm AUC}=\frac1P\sum_pd_p.
\]

事件级最佳通道 AUC 用同样的预算点和权重，只把命中条件换成“候选事件属于最低目录势垒事件集合”。

AUC∈[0,1]，d_p∈[−1,1]。AUC 增加 0.05 不是某个预算点增加五个百分点，也不是相对提升 5%。必须保留五个点的原始命中率供解释。

```python
import numpy as np

AUC_WEIGHTS = np.array([1, 2, 2, 2, 1], dtype=float) / 8.0

def prefix_auc(hits):
    y = np.asarray(hits, dtype=float)
    if y.shape[-1] != 5:
        raise ValueError("expected budgets 4,8,16,32,64")
    if not np.isfinite(y).all() or np.any((y < 0) | (y > 1)):
        raise ValueError("invalid hit values")
    if np.any(np.diff(y, axis=-1) < 0):
        raise ValueError("cumulative recall must be monotone")
    return y @ AUC_WEIGHTS

def parent_auc_difference(a2_hits, b1_hits):
    a = np.asarray(a2_hits, dtype=float)
    b = np.asarray(b1_hits, dtype=float)
    if a.shape != b.shape or a.ndim != 3 or a.shape[1:] != (3, 5):
        raise ValueError("shape must be [parents,3 training seeds,5 budgets]")
    return (prefix_auc(b) - prefix_auc(a)).mean(axis=1)
```

同一个母体五个预算点高度相关；不能把它们作为五个独立实验取平均 p 值。AUC 已经完成预设的聚合。

### 9.2 主推断按分子式聚类

主分析用分子式聚类的 sandwich 标准误，加 t(G−1) 临界值。对母体差值 d_p：

\[
S_g=\sum_{p\in g}(d_p-\bar d),\qquad
SE(\bar d)=\frac1P
\sqrt{\frac{G}{G-1}\sum_g S_g^2}.
\]

主界限：

\[
L^{one95}=\bar d-t_{G-1,0.95}SE,\qquad
U^{one95}=\bar d+t_{G-1,0.95}SE.
\]

每一个端点分别是单侧 95% 界限；两者合在一起是双侧 90% 区间。面向报告的双侧 95% 区间另用 t 的 0.975 分位数，不能混称。

```python
from scipy.stats import t
import numpy as np

def cluster_summary(values, formula_of):
    d = np.asarray(values, dtype=float)
    groups = np.asarray(formula_of, dtype=str)
    if d.ndim != 1 or groups.shape != d.shape or len(d) < 2:
        raise ValueError("one complete value per parent required")
    if not np.isfinite(d).all():
        raise ValueError("missing values must be resolved upstream")
    keys = np.unique(groups)
    g = len(keys)
    if g < 2:
        raise ValueError("at least two independent formula groups required")
    mean = float(d.mean())
    scores = np.array([(d[groups == key] - mean).sum() for key in keys])
    se = float(np.sqrt(g / (g - 1) * np.square(scores).sum()) / len(d))
    if se <= 1e-12:
        return {
            "estimate": mean, "se_cluster": se,
            "lower_one95": -1.0, "upper_one95": 1.0,
            "ci_two95": [-1.0, 1.0],
            "n_parents": len(d), "n_formula_groups": g,
            "status": "DEGENERATE_VARIANCE",
            "scope": "conservative support bounds; t inference unresolved"
        }
    q_one = float(t.ppf(0.95, g - 1))
    q_two = float(t.ppf(0.975, g - 1))
    return {
        "estimate": mean, "se_cluster": se,
        "lower_one95": mean - q_one * se,
        "upper_one95": mean + q_one * se,
        "ci_two95": [mean - q_two * se, mean + q_two * se],
        "n_parents": len(d), "n_formula_groups": g,
        "scope": "conditional on frozen models and specified evaluation design"
    }
```

对 \(m^{(0)}_p\) 与 \(m^{(R)}_p\) 分别使用同一个函数。绝不能把 3×8×3 个脉冲结果直接传进该函数并给它们伪造不同 formula。

组大小不等时依然使用母体宏平均和上式，不能改为先等权平均每个分子式而保留同样的指标名。

### 9.3 区间的适用范围

上述推断依赖分子式之间可视为独立的工作假设；少数组、极不均衡组或强异质性时，名义置信度不保证准确。正式冻结需报告 G、最大组占比及开发重采样中的错误率。

按分子式整组、保留臂配对的 bootstrap 做敏感性分析；不能看到哪种区间更容易 GO 就选哪种。主推断始终是本节的聚类 t 界限。

五折 OOF 的训练集彼此重叠。仅对已生成的 OOF 预测表做聚类，不能估计重训练造成的折间依赖，也不是整个学习算法的精确置信区间。若使用 OOF 路径，功效报告必须把这种额外训练依赖列为未覆盖的不确定性，并用开发重复切分或已有多训练 seed 检查其量级。不能把下面独立组工作模型的 80% 称作经过验证的 OOF 算法功效。

### 9.4 先规划两个效应

默认规划效应为：

| 指标 | 假定目标真效应 | 单侧检验方向 |
| --- | ---: | --- |
| 主 AUC 差 Δ_AUC | +0.05 | B1>A2 |
| 机制对比 M_0 = E[U(F_S)−U(F0)] | +0.02 | 评分方向胜过不干预 |
| 机制对比 M_R = E[U(F_S)−U(F_R)] | +0.02 | 评分方向胜过等幅随机方向 |

这些数是本轮资源决策希望能够识别的幅度，不是实测结果，不是统一的“百分比提升”。如果项目认为其他幅度才值得投入，应在正式结果前修改一次并记录原因。

目标是：在所规划的效应同时成立时，**V1a 统计闸门的联合 GO 概率至少 80%**。一种保守规划方法是主比较与机制闸门（两项对比都通过且都未触发停止）各自包含资源 futility 的完整门槛分别至少 90%，因为：

\[
P(\text{二者均过})\ge1-0.10-0.10=0.80.
\]

这个下界无需两项独立，但不包含数据缺陷、执行中断或 V1b 的 DFT 认证成功率。两个 90% 都必须包含第 10 节各自的资源 futility，不能只用“下界大于零”的通过率。

### 9.8 冻结 N 的实际流程

1. 在独立开发集上按正式定义得到 d_p、\(m^{(0)}_p\)、\(m^{(R)}_p\)；不得使用正式效应估计。开发集只运行训练 seed 0，可降低开发成本；正式集的三 seed 平均通常使 SD 更小，规划时不计入这一好处。
2. 记录三者 SD、差值 ICC、分子式组大小、两项机制对比之间的相关和跨指标相关。
3. 从 200 到 350 的可行分组名单，按预先随机顺序选择候选 N；保留完整分子式组。
4. 用开发 nuisance 参数和保守敏感性范围模拟完整闸门，包含零主效应、零机制效应、小有用效应和目标效应。
5. 要求名义错误推进率没有明显膨胀，目标情形联合功效≥0.80；同时报告 NO-GO/HOLD 概率。
6. 达到目标后冻结最终名单、N、G、随机顺序、分析函数及 hash。
7. 若需要 N>350，报告 `HOLD_POWER`。在正式揭盲前，可选择扩展 OOF、新资源预算或改变研究问题；不能写“350 也应该差不多”。
8. 正式运行只分析一次。看结果后再加样本属于新版本/新的确认研究，不能直接并回原固定样本检验。

优先按 300 个母体估算资源，再用开发结果决定落在 200–350 内的哪一点。二元近似里的 240 不再是默认功效承诺；v2.1 闸门在原工作假设下约需 320。

## 10. 任务 6：一次最终分析与推进闸门

**输入：** 冻结清单、完整候选流、主/机制统计摘要。  
**输出：** `gate.json`、结果报告、V1b 源总体。  
**完成标准：** 一个预设决策，范围明确；不靠挑预算、挑 seed、挑幅度得到 GO。

### 10.1 分析完整性先于数值判断

正式比较必须满足：

- 训练隔离和只读目录边界正确；
- 五臂使用正确权重、共享评分和公平成本；
- 正式母体及三个训练 seed 的模型全部完成，外部中断得到恢复；
- 主匹配和机制回放没有未解决实现错误；
- 网络调用成本表、引导结束时刻 `t_x,stop` 和 `B_M0re` 基线复核在揭盲前冻结；
- 功效规划在正式揭盲前冻结，未按正式结果调参。

这些是执行完整性条件，不是另五项需要达到显著性的实验结果。候选按算法正常失败仍是完整观察，不从母体分母删除。

### 10.2 统一推进闸门

按下列顺序判断：

1. 若主 AUC 单侧 95% 上界 \(U_A<0.05\)：`NO_GO_RESOURCE_SMALL`。
2. 否则，若 \(U(M_0)<0.02\) 或 \(U(M_R)<0.02\)：`NO_GO_MECHANISM_SMALL`。
3. 否则，若 \(L_A>0\)、\(L(M_0)>0\) 且 \(L(M_R)>0\)：`GO_V1b`。
4. 其余：`HOLD_INCONCLUSIVE`；若第 7.7 节的限定窗口停止已经成立，可将不推进的原因写为 `NO_GO_WINDOW_THIS_CONFIG`。

资源停止优先。若一个极小的正效应已经统计显著，但整个区间低于相应资源目标，仍停止这条投入路线。机制 NO-GO 排除的是任一对比达到有用幅度 0.02，不是证明对比≤0；这使“主效应有收益但机制不足”的精确结果不再默认进入 HOLD。

GO 的精确含义是“观察到正的效率证据，且评分方向平均同时胜过不干预和随机方向，尚未排除各自目标收益幅度，值得花钱认证”。它**没有证明 AUC 至少增加 0.05，也没有证明 M_0、M_R 至少增加 0.02**。

### 10.3 决策函数

```python
def decide_v1a(integrity_ok, complete, power_plan_frozen,
               primary, mech_vs_none, mech_vs_random,
               window_stop_supported=False):
    import math
    if not integrity_ok:
        return {"decision": "HOLD_IMPLEMENTATION", "reason": "invalid_comparison"}
    if not complete:
        return {"decision": "HOLD_INCOMPLETE", "reason": "restore_paired_units"}
    if not power_plan_frozen:
        return {"decision": "HOLD_POWER", "reason": "no_pre_screen_power_plan"}

    needed = ("lower_one95", "upper_one95")
    for summary in (primary, mech_vs_none, mech_vs_random):
        if any(k not in summary for k in needed):
            raise ValueError("missing one-sided confidence limits")
        if any(not math.isfinite(summary[k]) for k in needed):
            raise ValueError("nonfinite confidence limits")
        if summary["lower_one95"] > summary["upper_one95"]:
            raise ValueError("inverted confidence limits")

    if primary["upper_one95"] < 0.05:
        return {"decision": "NO_GO_RESOURCE_SMALL", "reason": "target_gain_excluded"}

    if mech_vs_none["upper_one95"] < 0.02 or mech_vs_random["upper_one95"] < 0.02:
        return {"decision": "NO_GO_MECHANISM_SMALL", "reason": "useful_mechanism_gain_excluded"}

    if (primary["lower_one95"] > 0 and mech_vs_none["lower_one95"] > 0
            and mech_vs_random["lower_one95"] > 0):
        return {"decision": "GO_V1b", "reason": "positive_efficiency_and_mechanism"}

    if window_stop_supported:
        return {"decision": "NO_GO_WINDOW_THIS_CONFIG",
                "reason": "no_supported_response_in_tested_window"}

    return {"decision": "HOLD_INCONCLUSIVE", "reason": "fixed_sample_not_decisive"}
```

生产实现还须核对来源 hash 一致。窗口子原因只细化未通过统计 GO 的结果，不另加一道会被遗漏在功效模型外的 GO 条件。

### 10.4 不再加入的并列闸门

以下内容必须报告，但不要求全部单独通过：

- 每个预算点均显著；
- 至少两个训练 seed 为正（逐 seed 结果必须报告）；
- 事件级最佳通道 AUC 显著（必报，见第 6.6 节解释规则）；
- 净胜母体至少 2；
- 至少发现 2 个有益事件改变；
- H/L 同时显著；
- 不同通道数达到另一个小样本比例；
- B1−B0、B1−B2、稀有层效应全部显著；
- 每个分子式留一后仍达到同样阈值。

如果诊断揭示真实泄漏、计费错误或控制分支实现错误，则按完整性问题暂停；不能把“我不喜欢这项诊断”变成事后新增的统计否决条件。

### 10.5 HOLD 不变成无限延长

正式 N 跑完后的 HOLD，应给出能决定下一步的信息：

- 主效应或机制哪一个区间限制了判断；
- 若要达到规划精度，预计还需要多少新独立组；
- 已知先验稀有层、预算饱和或评分支持是否解释差异；
- 是否值得另起一个预先规定的新实验。

本轮不自动增加 DFT；也不重新分析多次直到显著。资源上限用尽后，可将项目状态写为“当前配置暂停投入，统计结论未定”，而不是“证明 H1 不成立”。

## 11. 资源与一周推进节奏

### 11.1 先算工作量，再报小时

设外层训练数 F，训练 seed 数 R_train：

| 工作 | 运行数或计算方式 |
| --- | --- |
| 生成器训练 | 3×F×R_train，分别为 g/h/f |
| 基线复核模型 `B_M0re` | F 个单时间联合模型（训练 seed 0） |
| 势垒头训练 | 2 类×3 成员×F，跨训练 seed 共享 |
| 正式五臂 | P×3 训练 seeds×5 臂，各到 64 个 B0 等效候选 |
| 罕见度探查 | P×128 个 B0 候选（训练 seed 0） |
| 正式脉冲 | P×3×8×10 个逻辑终局，复用前缀 |
| 连续 B1/B2 控制 | P×3×8×2 个逻辑终局 |
| 目录匹配 | 全部效率与机制输出，CPU/GPU 实际消耗单列 |
| 新增量化 | 0 |

默认 R_train=3。单次留出需要 9 个生成器训练运行加 1 个 `B_M0re`；五折则分别为 45 个和 5 个。按 M0 实测单次约 0.45 GPU 小时，单次留出的训练约 4.5 GPU 小时。相对 v2.0 的“1 训练 seed × 3 采样 seed”，五臂与脉冲的评估工作量不变。已验证可复用的角色在表中扣除，同时给出依据。

### 11.2 总成本与墙钟

\[
T_{GPU}=
T_{train}+T_{score}+T_{dev}+T_{efficiency}
+T_{rarity}+T_{mechanism}+T_{retry}.
\]

批次并行、GPU 数、排队、存储和 CPU 匹配决定墙钟。资源预测至少给中位与保守上限，不把 GPU 小时直接当日历小时。

默认设一份已核准的 `gpu_hours_cap`；数值来自实际可用资源与开发测速，正文不预填 100 或 150 小时。接近上限时按冻结任务优先级停止整批新任务，不删除已完成的坏结果。

### 11.3 建议工作日

| 工作日 | 主要动作 | 当天交付 |
| --- | --- | --- |
| D1 | 数据、分子式分布、检查点、网络调用成本表核验 | 可复用资产、实际独立组数、资源预测 |
| D2 | 目录匹配、输入边界、评分标签 | 冻结目录候选、关键数值测试 |
| D2–D3 | 三个训练 seed 的生成器、`B_M0re` 与评分头训练 | 训练日志、基线复核、开发校准 |
| D3–D4 | 时间窗、A2 首轮、引导强度、引导漂移检查、功效规划 | 一次冻结，明确最终 N 与 `t_x,stop` |
| D4–D6 | 五臂、罕见度、正式脉冲与 B2 | 完整同流前缀和配对日志 |
| D7 | 单次分析、范围解释、V1b 源总体 | GO/HOLD/NO-GO 与两阶段接口 |

如果 D1 发现必须五折重训，一周只能作为重新估算后的目标。先交付可信的训练/评估时间表，不压缩样本量来维护一个没有计算依据的 D7 承诺。

### 11.4 日常检查只看执行问题

正式冻结后，允许查看任务完成数、资源、异常、文件缺失、非有限输出和缓存命中。不根据当前 B1−A2、最优幅度或最优预算改配置。

GPU 中断恢复沿同一语义随机键，已花成本保留。重新运行同一个候选不产生新 proposal，不把失败缓存丢掉后重新开始计时。

## 13. 最终报告与交接格式

### 13.1 报告顺序

1. 首句写结论、主差值及双侧 95% 区间、单侧推进界限、P/G。
2. 明确这是有限目录代理筛查；没有新量化结果。
3. 展示五臂的 5 个成本点曲线与每点候选数。
4. 给出 AUC 主比较和 16 单位二元差，不挑显著的替代主项。
5. 给出机制闸门的两项 M_0、M_R 及其界限，分幅度结果与事件转移。
6. 给出事件级最佳通道 AUC、引导漂移检查与冻结的 `t_x,stop`、B0/`B_M0re` 开发复核、B1/B2 控制、逐训练 seed 结果和罕见度分层。
7. 给出未知事件、几何不匹配、fallback、数值失败与成本。
8. 展示开发功效计划、实际独立组数及适用范围。
9. 输出 V1b 预算 16、训练 seed 0 的冻结源总体、母体—臂代理标签、最佳事件候选列表与 hash。
10. 明确下一步：启动 V1b、当前配置停止投入，或独立新实验需求。

### 13.2 不能出现的结论

| 不成立的写法 | 应使用的表述 |
| --- | --- |
| “B1 已发现更多真实低势垒 TS” | “B1 在有限目录代理上有更高召回，待 V1b 认证” |
| “T1x 与 H 同层级，所以所有 TS 都是真实的” | “可复用目录能量；驻点与连通性仍需认证” |
| “没计新通道，因此结果只会低估 B1” | “目录不完整，比较偏差方向未知” |
| “3 个训练 seed 估计了重训练方差” | “条件于这三次训练的平均结果；逐 seed 结果仅作一致性描述” |
