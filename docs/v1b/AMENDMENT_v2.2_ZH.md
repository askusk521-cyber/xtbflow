# xtbflow V1b 修订草案 v2.2（相对 v2.1）

2026-10-08 · **草案，未冻结。** 负责人批准前 V1b 不冻结、不提交任何正式 H 计算；本草案没有运行任何量化。配套：《xtbflow V1b 第一轮验证推进指导》v2.1（下称 v2.1）、V1a-R 重分析（`docs/evidence/v1a_r/REPORT_ZH.md`，探索性）。

## 0. 为什么修订

v2.1 的阶段 B 只认证 A2 和 B1，估计 Δ^cert(B1−A2)。V1a 正式结果与探索性的 V1a-R 重分析显示，这恰好是信息量最少的一对：B1−A2 的 AUC 差集中在 A2 几乎没有完成候选的预算点；无引导并联 B0 的 AUC 最高；候选数相同时，事件引导 A1 相对 A0 的单候选收益可分辨，几何引导 B1 相对 B0 几乎没有。

v2.2 保留 v2.1 的主决策（仍然认证 V1a 的 GO），并在同一批抽中母体上加认证 A1、B0，估计四个不设闸门的次要量。**估计量和决策规则由本交接写死；V1a-R 的结果只用于估计成本与方差、决定样本分配，不用于挑选估计量。**

## 1. 逐条修订

### 1.1 阶段 A 不变

五臂候选级分层审计（v2.1 第 3.2、9 节）的总体、互斥层、单相 SRSWOR、HT 估计和随机种子 `v1b_candidate_A_v2_1` 均不变。

### 1.2 阶段 B 认证四臂：A1、A2、B0、B1

对每个抽中母体 p 和 a ∈ {A1, A2, B0, B1}，按 v2.1 第 6、8 节同一协议、同一单候选预算，判定 C\*[p,a]（预算 16、训练 seed 0、采样 seed 0 的 bundle 中预测事件属于 E\*_p 的候选）中的候选。认证命中 `best_cert_hit`、ε_cert = 1.0 kcal/mol、能量短路和 witness 停止规则（v2.1 第 1.2、10.2 节）对四臂相同。

**候选检查顺序（H 前冻结）。** 对 B0：先检查 S3a 截取集合内的 C\* 候选，再检查其余 C\* 候选；对 A1、B1：先检查 S3b 截取集合内的，再检查其余。每一段内部沿用 v2.1 规则：先 `MATCH_BEST`，再其余最佳事件候选，各按源完成顺序。截取集合内找到 witness 时，全集与截取集合的 Y^cert 同时为 1；截取集合内全部明确为 0 时，截取集合的 Y^cert 为 0，全集继续检查。顺序只影响找到 witness 前的费用，不改变 Y^cert 的定义。

### 1.3 主决策不变

唯一决策量仍是 Δ^cert(B1−A2)，预算 16、训练 seed 0，Δ^cert = Δ^proxy + D，Δ^proxy(B1−A2) = +0.0673（23/342）。区间方法、超几何切换条件与决策规则与 v2.1 第 10.4、10.5、11.3 节逐字相同：单侧 95% 下界 > 0 为 `V1A_CONFIRMED`，上界 ≤ 0 为 `V1A_OVERTURNED`，其余为 `V1B_INCONCLUSIVE`，影响主决策的未解决标签为 `INCOMPLETE_BOUNDS`。次要估计量不进入决策。

### 1.4 关键次要估计量（报告区间，不设闸门）

每个次要量都写成 Δ^cert(X−Y) = Δ^proxy(X−Y) + D(X−Y)，用 v2.1 第 11.3 节的 `paired_ht`（把 X、Y 两侧的 Y^cert 区间代入 B1、A2 两个位置）和与主决策相同的区间方法，报告点估计、单侧 95% 上下界（即双侧 90%）、区间方法和未完成范围。

| 编号 | 定义 | 视角 | Δ^proxy（源数据计算，预览） |
|---|---|---|---:|
| S1 | Δ^cert(B1−B0)，预算 16，两臂完整 bundle | 生成成本 | −0.2690 |
| S2 | Δ^cert(B1−A1)，预算 16，两臂完整 bundle | 事件引导与几何引导 | +0.0263 |
| S3a | B1 完整 bundle 对 B0 截取集合：n_p = B1 在预算 16 的完成候选数，B0 只用其流中前 n_p 个候选 | 同候选数，单候选质量 | 0.0000 |
| S3b | n_p = min(B1, A1 在预算 16 的完成候选数)，两臂都只用前 n_p 个候选 | 同候选数，单候选质量 | −0.0234 |

Δ^proxy 预览由 `scripts/v1b_v22_plan.py` 从冻结源总体计算（`docs/v1b/amendment_v2.2_plan.json`）；正式值在 v2.2 的 D0 重冻结时写入 manifest。截取集合的代理标签 \(\widetilde Y\) 为"截取集合内存在 `hits_best_reference` 候选"，C\* 为截取集合与 `best_event_candidate_ids` 的交集。

### 1.5 分层调整

保留按 B1/A2 代理命中模式的分层，把 v2.1 的 `neither_empty` 拆成两层：

| v2.2 层 | 条件 | M_h | 处理 |
|---|---|---:|---|
| `B1_only` | \(\widetilde Y_{B1}=1,\ \widetilde Y_{A2}=0\) | 56 | 同 v2.1 |
| `A2_only` | \(\widetilde Y_{A2}=1,\ \widetilde Y_{B1}=0\) | 33 | 同 v2.1 |
| `both` | 两臂均代理命中 | 34 | 同 v2.1 |
| `neither_with_best_event` | 两臂均未命中，B1 或 A2 的 C\* 非空 | 44 | 同 v2.1 |
| `primary_empty_secondary_nonempty` | B1、A2 的 C\* 均为空，B0 或 A1 的 C\* 非空 | 80 | **新层**，分层 SRSWOR，m_h ≥ 2 |
| `all_empty` | 四臂及 S3 截取集合的 C\* 全部为空 | 95 | **新层**，包含概率 1 普查，不做量化，各差值贡献 0 |

S3 截取集合是对应臂 bundle 的子集，所以"四臂 C\* 全空"即蕴含截取集合 C\* 全空。

- **主估计量不受影响。** 两个新层里 B1、A2 的 C\* 都为空，Y^cert_{B1} = Y^cert_{A2} = 0 = 代理标签，主配对差恒为 0；拆层后主估计量的 HT 点估计与方差和 v2.1 相同。
- **次要估计量** 使用同一套母体包含概率 π_B = m_h/M_h。它们没有按 B0/A1 的代理命中模式分层，方差可能偏大，报告时注明。

### 1.6 成本超限时的删减顺序（预先写定）

1. 先删 S1：认证 B0 的完整 bundle 最贵，生成成本视角可由 V1a 代理结果和阶段 A 的 PPV 回答。删 S1 后 B0 只认证 S3a 截取集合内的 C\*。
2. 再删 S2。
3. S3a、S3b 始终保留：验证成本占主导时，比较的正是单候选质量。

删减只能在目标 H 结果出现前按资源表决定，删后重写并冻结配置；正式队列开始后不能因结果删层。

**源数据事实（不改变上述顺序）：** 本源总体中 S3b 的截取从未去掉任何 A1 的最佳事件候选（A1 截取集合与完整 bundle 的 |C\*| 分布完全相同），所以保留 S3b 时 A1 的完整 C\* 都要认证，删 S2 不节省任何链（见第 1.7 节表中"删 S1"与"删 S1+S2"两行相同）。

### 1.7 重算资源表

按 v2.1 第 13 节，用 D1 实测链成本和源数据的各臂 |C\*| 分布计算（`docs/v1b/amendment_v2.2_plan.json`）。

**D1 快照（2026-10-08 读取，D1 仍在进行，数值为暂定）：** 7 条完成的候选链（含失败链）单 GPU wall 时间中位 1347 s、最大 2253 s（6–18 原子；3 条 `STRICT_JOINT_GRAPH_VALID`，2 条 `PROTOCOL_FAILURE`，各 1 条 `IRC_REACTANT_MISMATCH`、`STRICT_EVENT_MISMATCH`）；1 条参考链 880 s；8 个锚点中位 124 s、最大 278 s。后端为 gpu4pyscf + geomeTRIC（负责人选择），单位为 GPU 小时而非 v2.1 的 core 小时。

**模型：** 不假设 witness 提前停止或能量短路，抽中母体的全部所需 C\* 候选都跑完整链；每个需量化的母体加 1 个锚点和全部原最佳参考链。中位估计 = 期望作业数 × 中位单价；保守上限 = 各层 |C\*| 最大的 m_h 个母体 × 最大单价。

### 1.8 导出截取集合

V1a 导出的源总体（`final/v1b_source_population.jsonl`，SHA256 `67036d6f…`）没有 S3 的截取集合。v2.2 的 D0 重冻结时按以下规则从冻结源总体推导，并与总体表一起写出、记录哈希：

1. bundle 的 `candidate_ids` 已按逻辑完成顺序排列（V1a `v1b_export` 取自流顺序）。
2. S3a：n_p = len(B1.candidate_ids)；B0 截取集合 = B0.candidate_ids[:n_p]。
3. S3b：n_p = min(len(B1.candidate_ids), len(A1.candidate_ids))；A1、B1 截取集合分别取各自前 n_p 个。
4. 截取集合的 C\* = 截取集合 ∩ `best_event_candidate_ids`（保持顺序）；代理标签 = 截取集合内存在 `hits_best_reference` 候选（取自冻结候选记录）。
5. 每行记录 `bundle_id`、`truncation`（S3a/S3b）、`n_p`、`candidate_ids`、`best_event_candidate_ids`、`proxy_best_reference_hit`、来源 bundle 的 `source_hash`，整表 SHA256 写入 D0 manifest。

`scripts/v1b_v22_plan.py` 已按此规则计算，并核对每个 bundle 与 V1a-R 抽取的流顺序一致（预算 16 前缀长度、最佳事件数、代理标签均相同）。
